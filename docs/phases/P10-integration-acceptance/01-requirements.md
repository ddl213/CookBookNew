# P10 · 全链路集成、非功能验证与交付

> 说明：本文件为从《美食家园》产品需求派生的阶段实施安排，阶段划分与顺序是执行规划，非原始需求新增功能。
> 产品权威来源：`docs/requirements/product/01-roles-and-functions.md`、`02-pages.md`、`03-quality-and-appendices.md`。

## 阶段目的
验证当前版本所有原有业务的跨模块一致性、性能/隐私基础和手动体验，形成项目交付结论；本阶段不是扩展新功能。

## 本阶段完整工作范围
1. 按产品附录 C 核对用户权限、五导航、菜谱 CRUD、可见性、搜索、好友关系、聊天、收藏评论分享、预订、双向订单、创作者发现与个人设置的完整链路。
2. 对主要跨页面数据一致性及安全边界做针对性复核：登录切换与隐私缓存、公开/好友访问隔离、重复预订、双视角订单、弱网/失败恢复。
3. UI/交互按 Figma 可用资源对照，覆盖至少典型屏宽与长文字/字体缩放、主要导航与操作、空状态、故障路径。
4. 本阶段允许依据原规则进行必要的受影响模块集成/全套回归；不无依据执行重复广域压力/付费在线接口测试。性能指标原文未给出数值，不能自称达到了未定义的 SLA。
5. 输出功能验收矩阵、未解决风险、证据与实际发布条件；涉及尚未确认的支付/群聊/社区功能只标未来规划，不作为本期交付缺陷。
6. 冻结获得用户接受的结果及失败历史，不篡改阶段已验收事实或假设尚未构建的后端正常工作。

## 最终 Gate
- 对应附录 C 已确认功能的关键检查有可复核依据；真实失败和待确认事项明确标记。
- 给出用户可重复执行的完整手工验收路径，收到明确最终接受后由进度 Agent 运行 `finish --user-accepted`。
- 若任一必要能力缺失，记录阻塞/修复并保持 P10 当前状态，不提前宣称整个 App 已完成。

## 需求引用与排除
映射产品文档第 4、5 章和附录 A、B、C、D，尤其以当前真实范围与用户批准规则为界，不自动新增未来规划。
