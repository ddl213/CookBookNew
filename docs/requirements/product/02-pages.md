## 3. 页面结构与功能说明

### 3.1 底部导航栏

【原有需求】底部始终保留五个主要入口，不新增、不合并、不更名：

| 底部入口 | 主要职责 | 关键关联内容 |
| --- | --- | --- |
| 首页 | 个性化推荐、好友动态与菜谱探索 | 搜索、分类列表、菜谱详情、好友主页 |
| 菜谱 | 个人已发布菜谱的管理 | 菜谱详情、创建菜谱 |
| 消息 | 好友聊天与预订通知 | 聊天详情、相关订单信息 |
| 订单 | 用户预订和销售订单的集中管理 | 我的订单、我的销售、订单详情 |
| 我的 | 用户资料和设置 | 收藏、好友、订单、设置、登录/注册 |

【落实说明】从五个入口进入的子页面应保持可理解的返回路径；由菜谱详情跳转到作者主页、再打开其他菜谱时，不应丢失用户原先浏览上下文。

### 3.2 首页（参考 `image_8f045d.png`）

**功能概述【原有需求】**：展示个性化推荐与好友动态，承担菜谱发现的主要入口。

**核心交互【原有需求】**

1. **折叠工具栏**：页面上滑时，搜索框逐渐折叠消失；折叠完成后在分类标签右侧显示搜索按钮。
2. **搜索框 / 搜索按钮**：进入菜谱或用户搜索。
3. **分类标签**：包含“推荐”“好友动态”“热门”“家常菜”“早餐”“甜品”等；点击切换至对应内容列表。
4. **菜谱卡片**：展示菜谱图片、名称、作者信息。
5. **好友动态**：作者头像可以进入好友主页，动态中的菜谱可以进入详情。

**页面跳转【原有需求】**

| 触发操作 | 目标位置 |
| --- | --- |
| 点击搜索框或折叠后的搜索按钮 | 搜索结果页 / 搜索流程 |
| 点击分类标签 | 对应分类列表内容 |
| 点击推荐、热门或好友动态中的菜谱 | 菜谱详情页 |
| 点击好友动态中的头像 | 好友主页 |
| 点击底部导航其他入口 | 对应主页面 |

**状态与交互补充【落实说明】**

- 展开与折叠状态下的搜索入口都应可用；折叠过程中避免搜索入口与分类标签重叠。
- 数据加载中、列表为空、网络请求失败时提供与页面风格一致的反馈，不误显示为“无权访问”。
- 分类切换与内容权限保持一致，好友动态不展示无访问权限的内容。

**验收关注点**：折叠后的搜索按钮位置、分类切换内容、菜谱/头像跳转、返回首页后的浏览体验。

### 3.3 菜谱页（参考 `image_8f049e.png`）

**功能概述【原有需求】**：个人菜谱管理中心，展示当前用户自己发布的菜谱。

**核心交互【原有需求】**

- 个人菜谱以卡片或列表方式展示。
- “+”按钮进入创建菜谱页面。
- 点击菜谱条目进入详情页。
- 创建、编辑或删除后的列表与菜谱实际数据保持一致。

**页面跳转**：菜谱条目 → 菜谱详情页；新增按钮 → 创建菜谱页。

**状态与交互补充【落实说明】**：没有已发布菜谱时显示空状态与现有新增入口；数据加载与失败时提供明确反馈。原文未决定草稿箱或批量管理功能，不作为本页面的既定要求。

**验收关注点**：只展示属于自己的菜谱、点击详情正确、新增入口可达、返回后列表更新。

### 3.4 消息页（参考 `image_8f049e.png`）

**功能概述【原有需求】**：集中管理好友聊天和订单通知。

**核心交互【原有需求】**

- 消息列表展示与好友的聊天记录，包括文字消息与预订通知等。
- 点击消息列表项进入对应聊天详情页。
- 与预订相关的通知需能让用户识别对应的预订事项。

**状态与交互补充【落实说明】**：无会话、消息加载失败或短暂断网时提供可理解的页面反馈；重连后不得将同一条发送结果重复展示为多条已发送消息。

**验收关注点**：好友会话准确、聊天详情跳转准确、预订通知与关联订单不混淆。

【待确认】订单通知在消息列表中是独立消息项、聊天内通知，还是两种方式并存；是否需要未读计数、已读回执等能力。

### 3.5 订单页（参考 `image_8f07c8.png`）

**功能概述【原有需求】**：统一管理用户发起的预订和收到的菜品预订。

**核心交互【原有需求】**

- 顶部具有“我的订单”和“我的销售”切换标签。
- 订单列表展示不同状态，例如“待接受”“待取货”。
- 点击列表项进入订单详情页。
- 作为提供方，可处理他人预订，执行接受、拒绝及备货等已有业务操作。

**状态与交互补充【落实说明】**

- 两个标签使用同一笔订单的对应角色视角，不应创建两笔不关联的独立订单。
- 接受/拒绝操作提交时，需避免连续点击造成重复处理；提交结果应更新对应双方所见的订单状态。
- 无订单、加载中、操作失败时显示明确反馈；操作失败不应伪装成成功。

**验收关注点**：预订订单进入“我的订单”、收到的订单进入“我的销售”、双方订单数据一致、订单详情跳转正确。

### 3.6 我的页（参考 `image_8f04c1.png`）

**功能概述【原有需求】**：个人信息与应用设置中心。

**核心交互【原有需求】**

- 个人资料卡：展示头像、昵称、ID。
- 功能入口：我的收藏、我的好友、我的订单等。
- 设置按钮：进入设置页，包含隐私设置、通知设置及应用帮助等内容。
- 未登录状态：展示“登录/注册”和“浏览应用”按钮。

**页面跳转【原有需求】**：设置按钮 → 设置页；登录/注册 → 登录/注册页；其他功能入口进入相应页面。

**状态与交互补充【落实说明】**：未登录状态与已登录状态展示对应信息；用户资料加载失败时不能用其他用户的资料替代；“浏览应用”的可访问范围需遵循最终确认的未登录权限规则。

**验收关注点**：用户资料准确、入口与页面对应、未登录引导清晰。

### 3.7 菜谱详情页（参考 `image_8f0821.png`）

**功能概述【原有需求】**：完整展示一份菜谱的详细内容，并承载收藏、分享和预订入口。

**核心内容【原有需求】**

- 菜谱信息区：菜品图片、名称、作者信息。
- 正文内容区：菜谱简介、食材清单、制作步骤。
- 交互操作：收藏、分享、“加入购物车（预订）”。
- 与核心功能一致的评论能力应能够访问，但原文未指定评论区具体布局。

**页面跳转【原有需求】**：作者头像 → 作者主页；分享按钮 → 分享弹窗；预订入口 → 预订确认弹窗。

**状态与交互补充【落实说明】**

- 收藏状态与“我的收藏”保持一致；分享入口不能让无权限用户绕过菜谱可见性。
- 预订入口遵循“当前仅好友之间预订”的业务范围，不能把所有公开菜谱默认视为可预订。
- 菜谱被删除、当前用户失去查看资格、数据加载失败时提供不同的有效提示，避免展示不应查看的内容。

**验收关注点**：内容完整性、作者跳转、收藏一致性、分享权限及预订确认入口。

### 3.8 美食创作者 / 公共菜谱页（参考 `image_8f0801.png`）

**功能概述【原有需求】**：发现美食创作者并浏览公开菜谱。

**核心交互【原有需求】**

- “推荐大师”与“公开菜谱”两种展示标签。
- 创作者卡片：推荐或附近用户的头像、昵称。
- 菜谱列表：所有人可见的公共菜谱。

**页面跳转【原有需求】**：创作者头像 → 创作者主页；菜谱列表项 → 菜谱详情页。

**状态与交互补充【落实说明】**：两个标签之间切换时保持内容与标签一致；公共菜谱不混入好友专属内容。若出现“附近”信息，应尊重定位权限以及用户设置。

【待确认】“推荐大师”与普通美食创作者之间是否有认证或筛选标准，以及“附近”的距离与定位数据来源。现阶段不新增认证体系。

### 3.9 菜品预订详情页

**功能概述【原有需求】**：展示某位好友可供预订的菜品及相关信息。

**核心交互【原有需求】**

- 好友信息：头像、昵称、评分、预计送达时间等。
- 可订购菜品列表：该好友公开展示且允许被当前用户预订的菜谱。
- “加入购物车”按钮：用于发起对应菜品的预订流程。

**页面跳转【原有需求】**：菜谱条目 → 菜谱详情页；“加入购物车” → 预订确认弹窗。

**状态与交互补充【落实说明】**：页面只展示当前用户有权查看、且符合预订规则的菜品；无可预订菜品时显示空状态。评分与预计送达时间应来自真实业务数据或明确的界面占位策略，不应伪造数值。

【待确认】评分来源、预计送达时间的计算规则、是否支持数量及多菜品预订。保留原有字段与入口，规则确定前不擅自扩展。
