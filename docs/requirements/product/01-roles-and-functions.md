## 1. 用户角色与权限

### 1.1 用户体系

【原有需求】应用使用同一套用户体系，功能上为了便于描述，区分“普通用户”和“美食创作者”两种身份。两者**不是必须分开注册的两个账号角色**；用户既可以浏览、预订他人的菜品，也可以发布自己的菜谱并处理收到的预订。

### 1.2 普通用户

【原有需求】普通用户可以：

1. 浏览所有向公众开放的菜谱，以及自己有权查看的好友动态。
2. 与好友进行一对一聊天。
3. 预订好友提供的、允许被预订的菜品。
4. 查看和管理自己发起的订单。
5. 对有权访问的美食创作者菜谱进行评论与收藏。
6. 管理个人资料和应用设置。
7. （可选）选择是否向陌生人隐藏部分个人信息。

### 1.3 美食创作者

【原有需求】美食创作者包含普通用户的所有能力，另外可以：

1. 创建、编辑、删除自己发布的菜谱。
2. 设置菜谱可见性：**好友可见 / 所有人可见**。
3. 接受或拒绝来自好友的菜品预订。
4. 通过“我的销售”管理别人对自己菜品发起的订单，并进行接单、备货等操作。
5. 【未来规划】为预订设置额外条件，例如语音、视频、文字或其他约定事项，以及收费选项。

### 1.4 权限边界

【落实说明】权限判定遵守以下原则，不增加新的用户角色：

- 用户仅能编辑、删除自己发布的菜谱；只能处理与自己有关的预订或销售订单。
- “所有人可见”用于公共内容浏览；“好友可见”仅向满足好友关系和访问条件的用户展示，不能因搜索、推荐、分享链接等入口绕过限制。
- **可浏览菜谱不等于可预订菜品**。当前菜品预订范围仍是好友之间，具体按钮是否可点应与好友关系、可预订状态保持一致。
- 聊天与订单详情仅向相关用户开放；界面隐藏不是服务端权限校验的替代。
- 【待确认】未登录时哪些内容允许浏览、哪些操作要求登录，以及登录后应如何回到原操作位置；现有文档仅明确“我的”页有“登录/注册”和“浏览应用”。

## 2. 核心功能

### 2.1 菜谱管理

【原有需求】用户可创建、编辑、删除自己的菜谱，设置“好友可见”或“所有人可见”。菜谱可在个人菜谱页和有权访问的内容列表中查看，并进入菜谱详情。

**已有信息字段：**菜品图片、名称、作者信息、菜谱简介、食材清单、制作步骤。首页还存在分类展示，因此菜谱需要具备与分类展示匹配的信息；具体编辑字段与是否必填以发布页面设计为准。

【落实说明】

- 新建、修改与删除后的展示结果，应同步反映在个人菜谱列表、菜谱详情和相关内容列表中。
- 编辑可见性后，所有访问入口应使用当前有效的可见范围，而不是继续展示先前缓存的内容。
- 原文未定义草稿、审核、发布次数限制、图片上限或删除后已有订单如何显示，不擅自补充固定规则。

### 2.2 社交互动

**聊天【原有需求】**：好友之间一对一即时聊天；消息中心同时承载聊天记录与预订通知。

**菜谱分享【原有需求】**：向好友分享自己的菜谱；被分享者能否打开，仍遵守菜谱可见性。

**评论和收藏【原有需求】**：对有权访问的美食创作者菜谱发表评论与收藏；“我的收藏”提供个人收藏入口。

【落实说明】聊天、评论、分享不应突破好友关系、可见性与隐私限制。原文未要求群聊、关注体系、点赞排行榜或其他独立社交模块。

### 2.3 菜品预订

【原有需求】好友可以互相预订菜品，并由预订行为产生订单。现阶段预订**免费**；未来可能增加预订限制、额外服务或收费。

【落实说明】最小业务链路为：

1. 用户从有权访问的菜谱详情或好友可预订菜品列表发起预订。
2. 进入原文规定的“预订确认弹窗”，展示本次预订涉及的菜品及必要提示。
3. 用户确认后发起预订请求；成功后应能在“我的订单”找到该订单。
4. 提供菜品的好友可在“我的销售”查看预订，并执行接受或拒绝操作。
5. 双方从各自订单列表与消息入口查看相关进展。

**重点说明：**原设计使用“加入购物车”作为按钮文案，但页面跳转明确指向“预订确认弹窗”。因此本期**保留该按钮文案和跳转逻辑**，不能仅凭按钮名称推导出必须新增独立购物车页面、跨创作者合并结算或支付系统。

【待确认】一次预订是否可包含多个菜品、是否可填写数量或备注、预订人能否主动取消、拒单后的展示方式、订单何时认定完成，以及是否必须具备取货/送达确认。这些规则涉及完整订单状态流转，详见附录 B。

### 2.4 内容探索

- **好友动态【原有需求】**：首页查看好友分享的最新菜谱。
- **公共菜谱【原有需求】**：浏览所有用户设置为公开的菜谱。
- **分类内容【原有需求】**：通过“推荐”“好友动态”“热门”“家常菜”“早餐”“甜品”等标签快速切换相应内容。
- **个性化推荐【原有需求】**：根据用户偏好及浏览历史推荐菜谱和美食创作者。
- **创作者发现【原有需求】**：在“推荐大师 / 公开菜谱”入口查看推荐或附近的创作者，以及公开菜谱。

【落实说明】各内容入口需要使用一致的访问权限。缺少偏好或历史数据时的推荐策略、热门计算方法和附近创作者定位策略，原文未给出具体规则，列为待确认，不替换原有推荐目标。

### 2.5 订单管理

- **我的订单【原有需求】**：展示当前用户发起的菜品预订及其状态。
- **我的销售【原有需求】**：展示其他用户对当前用户菜品发起的预订，支持接单、拒绝及备货等已有操作。
- **订单状态【原有需求】**：已列举“待接受”“待取货”等状态，但未给出全部状态集合与状态迁移规则。

【落实说明】同一笔订单在预订方和提供方视角下应保持数据一致；不同列表可以有不同的操作入口，但不应出现互相矛盾的订单结果。

### 2.6 个人中心与设置

【原有需求】个人中心包含头像、昵称、ID 等用户信息，以及“我的收藏”“我的好友”“我的订单”等入口；设置包含隐私、通知、应用帮助等内容。

【落实说明】个人信息与隐私设置发生变更后，在个人页、好友主页、创作者卡片、聊天和菜谱作者信息等位置应按访问权限展示有效资料。是否开放更细粒度的隐私开关属于待确认项，不能直接增加为本期强制功能。
