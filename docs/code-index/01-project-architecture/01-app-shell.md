# 01-01 · 应用入口与基础架构

> 返回分类首页：[01-project-architecture.md](../01-project-architecture.md)。模块、路由与页面参数见 [02-modules-routes.md](02-modules-routes.md)。

**收录范围：**应用入口、五标签容器、Gradle 自动 include、Fragment/Activity 基类、ViewModel、路由框架与底部标签切换。

| ID | 类 / API / 资源入口 | 用途与优先复用场景 | 调用方式、前提和限制 | 定义文件（项目相对路径） | 真实调用位置 / 核查证据 |
| --- | --- | --- | --- | --- | --- |
| ARCH-001 | `MainActivity`、`MyApplication`、NavHostFragment | 应用单 Activity 入口；初始化 Application、MMKV、NavHost、路由表与启动会话恢复。 | `MainActivity` 继承 `BaseBindActivity`，`initView` 调用 `NRoute.init(this, navController)`；`initData` 用 `lifecycleScope.launch` 调用 `SessionManager.restore()`，网络异常在会话层内部处理，不阻塞 UI。`MyApplication` 先 `MMKV.initialize(this)` 再 `AppHelper.init(this)`，顺序不能反；随后调用 `ChatSessionGuard.start(this)` 按登录用户隔离聊天缓存（DATA-051），该调用幂等且依赖前两步完成。Manifest 固定 `portrait`、`singleTask`、`adjustResize`；启动页由 `@Route(startPage = true)` 决定为 `HomeFragment`。路由资源缺失时无法建图。 | `app/src/main/java/com/rhys/main/MainActivity.kt` | `app/src/main/AndroidManifest.xml`、`app/src/main/res/layout/activity_main.xml`、`app/src/main/java/com/rhys/main/MyApplication.kt`；`SessionManager.restore()` 见 BIZ-001；`ChatSessionGuard` 见 DATA-051；`HomeFragment` 的 `@Route(PAGE_HOME, startPage = true)`。 |
| ARCH-002 | `HomeFragment` 五标签导航容器 | 固定底部五入口：首页、菜谱、消息、订单、我的；ViewPager2 承载页面，MagicIndicator 显示底部栏，并对外提供标签切换。 | 标签名称、顺序和图标在 `HomeFragment` 硬编码；`vp.isUserInputEnabled = false`，只允许点击或 `switchTab` 切换；`offscreenPageLimit = 5`；`switchTab` 先检查 `view` 和下标，再 `setCurrentItem(index, false)`。新增、替换或重命名入口会改变产品固定导航，须产品授权。 | `app/src/main/java/com/rhys/main/home/HomeFragment.kt` | `fragment_home.xml`、`BottomBarItem.kt`、`layout_bottom_bar_item.xml`；实现 ARCH-010 `MainTabController`；五个一级页面均以 `@Route` 注册。 |
| ARCH-003 | Gradle 模块自动 include 与 app 聚合 | 新增 `subModules/lib_*` 目录后自动成为 Gradle 模块并被 app 依赖，减少手工改 settings。 | `settings.gradle.kts` 遍历 `subModules` 目录并 `include`；`app/build.gradle.kts` 对名称以 `lib_` 开头且不含 `compiler` 的模块逐个 `implementation`。模块名、Gradle 路径与 namespace 不一定相同；`lib_route_compiler` 只通过 KSP 接入。新增模块仍需在自身 build 文件声明依赖与 KSP；自动聚合不代表模块间依赖自动成立。 | `settings.gradle.kts` | `app/build.gradle.kts`、`gradle/libs.versions.toml`、各模块 `build.gradle.kts`；`P01-T02` 的 `:lib_auth`（DEP-009）与 `P02-T01` 的 `:lib_relation`（DEP-011）均由该规则自动纳入并被 app 聚合。 |
| ARCH-004 | `BaseBindFragment<V : ViewBinding>` | 统一 Fragment 的 ViewBinding 生命周期、沉浸式状态栏和初始化顺序。 | 子类实现 `initView`、`initData`；可选覆写 `initListener`、`initObserver`、`onViewDestroy`、`initTitleBar`、`getStatusBarColor`、`getStartBarDarkFont`。`onDestroyView` 会清空 binding，异步回调不得在销毁后继续访问；`initObserver` 中收集 Flow 应使用 `viewLifecycleOwner.repeatOnLifecycle`。 | `subModules/lib_android_common/src/main/java/com/android/common/base/BaseBindFragment.kt` | `HomeFragment`、`CookBookFragment`、`CookBookChildFragment`、`IndexFragment`、`MineFragment`、`ChatFragment`、`OrderFragment`、`AddRecipesFragment`；`LoginFragment`、`RegisterFragment` 覆写 `initTitleBar`；`FriendsFragment`、`FriendSearchFragment`、`FriendRequestsFragment`、`UserProfileFragment` 在 `initObserver` 收集登录态。 |
| ARCH-005 | `BaseBindActivity<V : ViewBinding>` | 统一 Activity 的 ViewBinding、沉浸式状态栏与初始化顺序。 | `onCreate` 中先 inflate binding，再依次调用 `initView`、`initListener`、`initData`；默认 `immersionBarDarkFont = true`；`onDestroy` 清空 binding。布局被额外包进竖向 `LinearLayout`，标题栏占位 View 高度为 0。 | `subModules/lib_android_common/src/main/java/com/android/common/base/BaseBindActivity.kt` | `app/src/main/java/com/rhys/main/MainActivity.kt` 继承；`activity_main.xml` 为实际内容布局。 |
| ARCH-006 | `BaseViewModel.launch` | 在 ViewModel 内启动协程，统一记录调用类/方法并捕获异常。 | 使用 `viewModelScope`；异常被 `LogUtils.e` 捕获后不再抛出，业务需自行暴露错误状态；仅适用于 ViewModel 生命周期。当前未见实际 `launch` 调用，`CookBookChildVM` 仅继承未使用。 | `subModules/lib_android_common/src/main/java/com/android/common/base/viewmodel/BaseViewModel.kt` | `subModules/lib_cookbook/src/main/java/com/rhys/cookbook/viewmodel/CookBookChildVM.kt`；全仓检索无 `launch {` 业务调用。 |
| ARCH-007 | `NRoute`、`@Route`、KSP 路由表 | 以注解声明 Fragment/Activity/Dialog 路由，启动时读取加密 nav 资源并动态构建 NavGraph。 | 页面类需标注 `@Route(path)`；Fragment 必须有无参构造；必须先执行 `NRoute.init` 再调用 `NRoute.getFragment`；nav 资源由 `lib_route_compiler` 写入 `app/src/main/assets/nav`，新页面需先构建；`startPage` 决定起始页。跳转使用 `NRoute.withNavController(...).deepLink(path).args(bundle).go()`。 | `subModules/lib_route_api/src/main/java/com/marky/route/api/NRoute.kt` | `subModules/lib_route_annotation/src/main/java/com/marky/route/annotation/Route.kt`、`subModules/lib_route_compiler/src/main/java/com/marky/route/compiler/processor/RouteProcessor.kt`；`HomeFragment` 与 `CookBookFragment` 的 `@Route` 及 `deepLink().go()`；`app/src/main/assets/nav/_nav*`（`P03-T01` 已重新生成）存在。 |
| ARCH-010 | `MainTabController.switchTab(index)` | 子页面请求宿主切回固定底部标签（如“我的”页“浏览应用”回到首页）。 | 接口在 `lib_campaign_common`；由承载 ViewPager2 的 `HomeFragment` 实现，索引固定 0 首页、1 菜谱、2 消息、3 订单、4 我的。子页面用 `parentFragment as? MainTabController` 获取，必须处理 null（宿主未实现或层级不符），不能假设切换一定成功；调用时还需注意 view 是否已销毁。 | `subModules/lib_campaign_common/src/main/java/com/campaign/common/listener/MainTabController.kt` | `HomeFragment.switchTab` 先检查 `view` 与下标再 `setCurrentItem`；`MineFragment.browseApp()` 使用 `parentFragment as? MainTabController`，失败时提示 `mine_browse_failed`；`MineFragment.openOrders()` 先取 `parentFragment` 再回退 `activity` 作为 `MainTabController`，调用 `switchTab(3)` 切入订单 Tab，失败提示 `mine_orders_failed`，不新开重复订单页。 |
