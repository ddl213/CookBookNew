# 01-02 · 模块、路由与页面参数

> 返回分类首页：[01-project-architecture.md](../01-project-architecture.md)。应用入口与基类见 [01-app-shell.md](01-app-shell.md)。

**收录范围：**页面路由常量、功能模块入口、路由参数约定；只登记可复用定位入口，不把路由常量当作已实现页面。

| ID | 类 / API / 资源入口 | 用途与优先复用场景 | 调用方式、前提和限制 | 定义文件（项目相对路径） | 真实调用位置 / 核查证据 |
| --- | --- | --- | --- | --- | --- |
| ARCH-008 | `RoutePath` 页面路径常量 | 集中声明页面路由字符串，避免页面间硬编码。 | 常量存在不代表页面已实现。`PAGE_LOGIN`、`PAGE_REGISTER`、`PAGE_FRIENDS`、`PAGE_FRIEND_SEARCH`、`PAGE_FRIEND_REQUESTS`、`PAGE_USER_PROFILE`、`PAGE_COOK_BOOK_CHILD`、`PAGE_COOK_BOOK_ADD` 已有 `@Route` 页面与真实跳转；`PAGE_NEAR_COOK_BOOK`、`PAGE_USER_COOK_BOOK`、`PAGE_COOK_BOOK_DETAIL`、`PAGE_ORDER_INFO`、`PAGE_CHAT_DETAIL`、`PAGE_ORDER_DETAIL`、`PAGE_SETTING`、`PAGE_ADDRESS_INFO`、`PAGE_ADD_ADDRESS`、`PAGE_MINE_INFO` 目前无实现类引用；`PAGE_INDEX_CHILD` 仅有 `@Route` 声明，未被导航调用。 | `subModules/lib_campaign_common/src/main/java/com/campaign/common/constants/RoutePath.kt` | `PAGE_COOK_BOOK_CHILD` 被 `CookBookFragment` 两个 Tab 与 `CookBookChildFragment` 的 `@Route` 使用；`PAGE_COOK_BOOK_ADD` 被 `CookBookFragment` 添加按钮、`CookBookChildFragment.openEdit()` 与 `AddRecipesFragment` 的 `@Route` 使用；登录、好友路由见 ARCH-009、ARCH-011。 |
| ARCH-009 | `:lib_auth` 认证模块（`LoginFragment`、`RegisterFragment`、`AuthValidator`） | 登录/注册页面与纯 Kotlin 表单校验的独立模块；新页面需要登录入口时优先复用其路由与 `SessionManager` 调用方式，不复制登录 UI。 | 命名空间 `com.rhys.auth`、`resourcePrefix = "auth_"`，由自动 include 规则纳入并被 app 聚合；依赖 `lib_network`、`lib_campaign_common`、`lib_android_common`、路由 API/注解与 KSP。页面以 `@Route(PAGE_LOGIN/PAGE_REGISTER)` 注册，依赖已生成的 nav 资源；只做表单校验和 `SessionManager.login/register`，不直接持有 Retrofit。注册成功会消费登录页回退栈；登录/注册切换使用 `popBackStack(path, false)` 避免重复入栈。 | `subModules/lib_auth/build.gradle.kts` | `src/main/java/com/rhys/auth/LoginFragment.kt`、`RegisterFragment.kt` 的 `@Route`；`MineFragment.openLogin()`、`CookBookChildFragment.openLogin()`、`AddRecipesFragment` 的 401 分支使用登录路由；`app/src/main/assets/nav/_navauth` 已生成。 |
| ARCH-011 | `:lib_relation` 好友关系与用户主页模块（4 个 Fragment） | 好友列表、用户搜索、好友申请、用户主页；相关新入口优先在该模块扩展并复用既有列表、标题栏与头像工具。 | 命名空间 `com.rhys.relation`、`resourcePrefix = "relation_"`，由 ARCH-003 自动 include 并被 app 聚合；依赖 `lib_android_common`、`lib_campaign_common`、`lib_network`、路由 API/注解与 KSP。页面以 `@Route(PAGE_FRIENDS/PAGE_FRIEND_SEARCH/PAGE_FRIEND_REQUESTS/PAGE_USER_PROFILE)` 注册，依赖已生成的 nav 资源；登录态来自 BIZ-001，数据来自 DATA-020/DATA-021。好友关系与可见菜谱均由后端判定，页面不得自行扩大权限。 | `subModules/lib_relation/build.gradle.kts` | `friend/FriendsFragment.kt`、`search/FriendSearchFragment.kt`、`request/FriendRequestsFragment.kt`、`profile/UserProfileFragment.kt` 的 `@Route`；`MineFragment.openFriends()` 调用 `deepLink(PAGE_FRIENDS)`；`app/src/main/assets/nav/_navrelation` 已生成。 |
| ARCH-012 | `Constants.KEY_USER_ID`、`openUserProfile`、`readUserIdArgument` | 用户主页路由参数约定：入口传 Long `userId`，主页兼容 Bundle 与 deep link query 读取，供好友/搜索结果等入口复用。 | `KEY_USER_ID` 在 `lib_campaign_common`；`openUserProfile` 对 `userId <= 0` 直接返回，否则 `Bundle.putLong` 后 `deepLink(PAGE_USER_PROFILE).args(bundle).go()`；`readUserIdArgument` 先读 Bundle `getLong`，再回退 `NRoute.getArgument(...).toLongOrNull()`，缺失/非法返回 0，页面按 `USER_NOT_FOUND` 处理。参数必须是可解析的 Long，不能传用户名或负数。 | `subModules/lib_campaign_common/src/main/java/com/campaign/common/constants/Constants.kt` | `RelationUiSupport.kt` 定义 `openUserProfile/readUserIdArgument`；`FriendsFragment`、`FriendSearchFragment`、`FriendRequestsFragment` 调用 `openUserProfile`；`UserProfileFragment.userId` 懒读取并校验。 |
| ARCH-013 | `:lib_cookbook` 菜谱发布与管理页面组（`CookBookFragment`、`CookBookChildFragment`、`AddRecipesFragment`） | 个人菜谱的已发布/草稿列表、新建/编辑表单；相关菜谱管理入口优先在该模块扩展，复用现有列表、表单与登录态处理。 | 命名空间 `com.rhys.cookbook`、`resourcePrefix = "cookbook_"`；依赖 `lib_android_common`、`lib_campaign_common`、`lib_network`、`lib_photo_view`、路由 API/注解，`androidx.activity.ktx` 用于 `PickVisualMedia`。列表按 `KEY_BUNDLE_PAGE_ID` 的 publish/draft 请求 `/recipes/mine?status`；编辑页用 ARCH-014 传 `recipeId`；删除 204 由 DATA-024 校验；草稿可见性与菜谱权限由后端判定，页面不扩大范围。 | `subModules/lib_cookbook/build.gradle.kts` | `CookBookFragment` 的已发布/草稿 Tab 与添加按钮；`CookBookChildFragment` 的 `@Route(PAGE_COOK_BOOK_CHILD)`；`AddRecipesFragment` 的 `@Route(PAGE_COOK_BOOK_ADD)`；`app/src/main/assets/nav/_navcookbook` 已重新生成。 |
| ARCH-014 | `Constants.KEY_BUNDLE_RECIPE_ID`、`AddRecipesFragment.readRecipeId` | 添加/编辑菜谱路由参数：调用方传菜谱 ID，表单缺省或非法时按新建处理。 | Key 在 `lib_campaign_common`；`readRecipeId` 先 `Bundle.getLong`，再回退 `NRoute.getArgument(...).toLongOrNull()`；`recipeId <= 0` 视为新建，编辑需要正数且后端可访问的 ID。列表编辑使用 `bundleOf(KEY_BUNDLE_RECIPE_ID to item.id)`；不要传名称/位置等非稳定标识。 | `subModules/lib_campaign_common/src/main/java/com/campaign/common/constants/Constants.kt` | `CookBookChildFragment.openEdit()` 传参；`AddRecipesFragment.recipeId` 懒读取并据 `isEditing` 决定 `loadRecipe()` 或新建表单。 |
