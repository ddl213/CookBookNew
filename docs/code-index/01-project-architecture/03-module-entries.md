# 01-02-02 · 功能模块入口

> 返回子类导航：[02-modules-routes.md](02-modules-routes.md)。应用入口与基类见 [01-app-shell.md](01-app-shell.md)，路由常量与页面参数见 [02-routes-pages.md](02-routes-pages.md)。

**收录范围：**`lib_auth`、`lib_relation`、`lib_cookbook` 功能模块的 Gradle 边界、页面注册与模块内复用约束。

| ID | 类 / API / 资源入口 | 用途与优先复用场景 | 调用方式、前提和限制 | 定义文件（项目相对路径） | 真实调用位置 / 核查证据 |
| --- | --- | --- | --- | --- | --- |
| ARCH-009 | `:lib_auth` 认证模块（`LoginFragment`、`RegisterFragment`、`AuthValidator`） | 登录/注册页面与纯 Kotlin 表单校验的独立模块；新页面需要登录入口时优先复用其路由与 `SessionManager` 调用方式，不复制登录 UI。 | 命名空间 `com.rhys.auth`、`resourcePrefix = "auth_"`，由自动 include 规则纳入并被 app 聚合；依赖 `lib_network`、`lib_campaign_common`、`lib_android_common`、路由 API/注解与 KSP。页面以 `@Route(PAGE_LOGIN/PAGE_REGISTER)` 注册，依赖已生成的 nav 资源；只做表单校验和 `SessionManager.login/register`，不直接持有 Retrofit。注册成功会消费登录页回退栈；登录/注册切换使用 `popBackStack(path, false)` 避免重复入栈。 | `subModules/lib_auth/build.gradle.kts` | `src/main/java/com/rhys/auth/LoginFragment.kt`、`RegisterFragment.kt` 的 `@Route`；`MineFragment.openLogin()`、`CookBookChildFragment.openLogin()`、`AddRecipesFragment` 的 401 分支使用登录路由；`app/src/main/assets/nav/_navauth` 已生成。 |
| ARCH-011 | `:lib_relation` 好友关系与用户主页模块（4 个 Fragment） | 好友列表、用户搜索、好友申请、用户主页；相关新入口优先在该模块扩展并复用既有列表、标题栏与头像工具。 | 命名空间 `com.rhys.relation`、`resourcePrefix = "relation_"`，由 ARCH-003 自动 include 并被 app 聚合；依赖 `lib_android_common`、`lib_campaign_common`、`lib_network`、路由 API/注解与 KSP。页面以 `@Route(PAGE_FRIENDS/PAGE_FRIEND_SEARCH/PAGE_FRIEND_REQUESTS/PAGE_USER_PROFILE)` 注册，依赖已生成的 nav 资源；登录态来自 BIZ-001，数据来自 DATA-020/DATA-021。申请/搜索页在同一 Fragment 的 View 重建后重新提交保留的数据快照，保留方向/查询/空态及下一页；销毁清在途锁，账号变化清数据，请求代次与当前用户过滤过期响应。`UserProfileFragment` 在 View 重建或同一 View 再次进入 STARTED 时用缓存 `profile` 重新 `renderProfile`，并向新 Adapter 重新 `submitList(recipes)`，避免返回后空白；已登录账号 id 变化时清空资料、菜谱、分页与待处理状态后重新拉取第一页。不是进程死亡恢复或持久缓存。好友关系与可见菜谱均由后端判定，页面不得自行扩大权限。 | `subModules/lib_relation/build.gradle.kts` | `friend/FriendsFragment.kt`、`search/FriendSearchFragment.kt`、`request/FriendRequestsFragment.kt`、`profile/UserProfileFragment.kt` 的 `@Route`；申请/搜索页 `onViewDestroy/renderAuthState/renderContent` 复用 ARCH-004 生命周期与列表提交；`UserProfileFragment.renderAuthState()` 在 STARTED/View 重建时用缓存 `profile` 回填并重新 `submitList`，账号切换分支清空后重新加载；回归入口见 TEST-013；`MineFragment.openFriends()` 调用 `deepLink(PAGE_FRIENDS)`；`UserProfileFragment.openRecipeDetail()` 以 `KEY_BUNDLE_RECIPE_ID` 跳转详情；`app/src/main/assets/nav/_navrelation` 已生成。 |
| ARCH-013 | `:lib_cookbook` 菜谱页面组（`CookBookFragment`、`CookBookChildFragment`、`AddRecipesFragment`、`CookBookDetailFragment`、`ShareFriendDialog`） | 个人菜谱的已发布/草稿列表、新建/编辑表单、详情与好友分享；相关菜谱入口优先在该模块扩展，复用现有列表、表单、详情与登录态处理。 | 命名空间 `com.rhys.cookbook`、`resourcePrefix = "cookbook_"`；依赖 `lib_android_common`、`lib_campaign_common`、`lib_network`、`lib_photo_view`、路由 API/注解，`androidx.activity.ktx` 用于 `PickVisualMedia`。列表按 `KEY_BUNDLE_PAGE_ID` 的 publish/draft 请求 `/recipes/mine?status`；编辑页与详情页用 ARCH-014 传 `recipeId`；删除 204 由 DATA-024 校验；详情页复用 DATA-024 的详情/评论/收藏/分享方法，匿名只读公开内容；草稿隐藏 `llActions` 整个操作区（收藏/分享/预订）及评论区/评论输入。详情根布局用 `ViewCompat.setOnApplyWindowInsetsListener` 读取 `WindowInsetsCompat.Type.ime()` 底部高度并写入根布局 bottom padding，避免键盘遮挡评论输入栏；评论分页按 `id` 去重并以 `sortBy { it.id }` 升序合并，保证先加载第 1 页、发表评论、再加载第 2 页仍为时间顺序。`ShareFriendDialog` 继承 VIEW-013 `BaseBottomSheetDialog`，仅负责好友列表与选择回调，分享请求由详情页发起。草稿可见性、收藏/分享资格与菜谱权限由后端判定，页面不扩大范围。 | `subModules/lib_cookbook/build.gradle.kts` | `CookBookFragment` 的已发布/草稿 Tab 与添加按钮；`CookBookChildFragment`（`PAGE_COOK_BOOK_CHILD`）卡片正文 `openDetail()`；`AddRecipesFragment`（`PAGE_COOK_BOOK_ADD`）；`CookBookDetailFragment`（`PAGE_COOK_BOOK_DETAIL`）的 `initView()` IME insets 监听、`renderSocialActions()/updateCommentInput()` 草稿隐藏、`loadComments()` id 去重与升序合并；`detail/ShareFriendDialog.kt`；`app/src/main/assets/nav/_navcookbook` 已重新生成。 |
