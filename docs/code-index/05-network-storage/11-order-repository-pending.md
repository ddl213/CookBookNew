# 05-11 · 订单 Repository 与待确认请求

> 返回分类首页：[05-network-storage.md](../05-network-storage.md)。订单接口/DTO 见 [09-order-network.md](09-order-network.md)，数据源见 [10-order-datasource.md](10-order-datasource.md)。

**收录范围：**订单数据访问层、创建幂等与超时恢复、待确认请求的 owner/数据源/baseUrl 隔离、MMKV 存储、AES-256-GCM/Keystore 加密、明文编解码。

**索引原则：**请求内容落盘前必须整体加密，禁止明文备注/明细；超时/IO/5xx 结果未知时保留原键原内容，不得自动换键重下单；只有明确 4xx 才能证明服务端未创建订单并清理 pending。

| DATA-063 | `OrderRepository`、`OrderCreatePendingException`、`OrderPendingConflictException` | 订单数据访问层：页面经本类读写订单；创建请求实现持久化幂等键与超时恢复，不直接依赖 Retrofit/Mock。 | 构造参数可注入 `OrderDataSource`（默认 DATA-061 工厂）、`OrderOwnerProvider`（默认 DATA-062）、`OrderPendingStore`（默认 DATA-064 MMKV）、`OrderPendingCipher`（默认 DATA-067 Keystore）、幂等键工厂、baseUrl provider 与时钟；默认面向生产。`isMock` 透传数据源，UI 必须据此标识演示模式。`createOrder` 先要求登录并归一化（DATA-057），按 owner + 数据源类型 + baseUrl 生成 scope；已有 pending 时：内容相同则用**原键原内容**重放，内容不同或不可读抛 `OrderPendingConflictException`，不静默新建。新请求先加密落盘再发送；成功或明确 4xx（`AuthException.httpStatus` 400..499）清理 pending，超时/IO/5xx/未知异常保留 pending 并抛 `OrderCreatePendingException`；协程取消也保留 pending 后原样重抛。成功后清理失败不回滚成功结果。`retryPendingCreate` 无 pending 抛 `ORDER_PENDING_NOT_FOUND`(404)，密文不可读抛 `ORDER_PENDING_UNREADABLE`(409)，网络仍失败继续保留。`pendingCreate()` 未登录返回 null；`discardPending()` 未登录不做事，仅清当前 scope。列表/详情/动作/整单取消只透传数据源结果，不做本地乐观状态；版本冲突原样上抛。未登录写操作抛 `UNAUTHORIZED`(401)。无统一重试队列、自动换键或离线队列。 | `subModules/lib_order/src/main/java/com/rhys/order/data/OrderRepository.kt` | 页面预计作为唯一消费方（P08 后续任务）；测试为 `OrderRepositoryTest`（TEST-034）与 `OrderRepositoryPendingTest`（TEST-033，16 例）；依赖 DATA-057～DATA-068。 |
| DATA-064 | `OrderPendingScope`、`PendingOrderCreate`、`OrderPendingStore`、`MmkvOrderPendingStore` | 待确认创建请求的隔离维度、数据结构与 MMKV 持久化边界。 | `OrderPendingScope(ownerId, kind, baseUrl)` 三元组必须同时隔离：账号、Mock/Remote 数据源、后端环境不得串用 pending。`PendingOrderCreate(idempotencyKey, items, note?, createdAt, readable)`；`readable=false` 表示密文损坏或密钥不可用，只能提示放弃后重提，仍保留明文幂等键用于展示/排查。存储内容只包含幂等键明文与加密后的规范化请求，禁止明文落盘备注/明细。生产 `MmkvOrderPendingStore` 使用项目已有 `MMKVUtils`，键前缀 `order_pending_create_v1`，结构 `前缀_ownerId_数据源小写_SHA-256(baseUrl)前16位`；`read` 空值返回 null，`write/clear` 按 scope 操作。测试应注入内存实现。 | `subModules/lib_order/src/main/java/com/rhys/order/data/pending/OrderPendingStore.kt` | `OrderRepository` 默认 `MmkvOrderPendingStore()`（DATA-063）；`OrderRepositoryPendingTest`（TEST-033）覆盖 owner/数据源/baseUrl 隔离、无明文备注与清空。 |
| DATA-065 | `OrderPendingCipher`、`OrderPendingDecryption`、`OrderPendingCipherException` | 待确认请求字段加密契约；所有 pending 明文在落盘前必须经本接口。 | `encrypt` 必须返回密文，失败抛 `OrderPendingCipherException`，禁止回退明文；`decrypt` 对密钥失效、密文损坏、格式不支持等任何失败返回 `OrderPendingDecryption.Unavailable`，不得崩溃或猜测内容。只加密请求内容（明细与备注），幂等键以明文元数据保存以便定位/丢弃。新增加密实现必须保持相同失败语义；异常 message 可展示且不得包含明文。 | `subModules/lib_order/src/main/java/com/rhys/order/data/pending/OrderPendingCipher.kt` | `OrderRepository.persistPending/readPending`（DATA-063）使用；默认 DATA-067，测试注入 DATA-066。 |
| DATA-066 | `AesGcmOrderPendingCipher` | AES-256-GCM 待确认请求加密实现；JVM 测试与 Keystore 生产实现共用。 | 转换 `AES/GCM/NoPadding`、128-bit tag，每次加密随机 IV；密文格式固定 `v1:<hex iv>:<hex ciphertext>`，使用十六进制而非 Android Base64，使纯 JVM 单测可用。密钥由 `keyProvider: () -> SecretKey` 提供。解密要求 3 段、版本 `v1`、IV 非空、payload 不短于 16 字节，否则返回 `Unavailable`；GCM 空明文合法。加密异常转 `OrderPendingCipherException`，不返回明文。JVM 单测需自行生成 AES 密钥。 | `subModules/lib_order/src/main/java/com/rhys/order/data/pending/AesGcmOrderPendingCipher.kt` | `KeystoreOrderPendingCipher` 委托本实现（DATA-067）；`OrderRepositoryPendingTest`（TEST-033）用 `KeyGenerator` 生成 JVM 密钥验证加密落盘与解密失败分支。 |
| DATA-067 | `KeystoreOrderPendingCipher` | 生产默认订单待确认加密：Android Keystore 保存 AES-256 密钥。 | 默认别名 `cookbook_order_pending_v1`，首次使用时在 `AndroidKeyStore` 生成 AES-256-GCM 密钥并缓存；进程级锁 + double-check 保证并发首次只生成一把密钥，避免新旧密钥覆盖导致已落盘密文永久不可解。密钥不可用（系统清除、Keystore 缺失）时加密抛 `OrderPendingCipherException`，解密返回 `Unavailable`，绝不回退明文。别名变更或密钥丢失会使旧密文永久不可解；依赖 Android 运行时，纯 JVM 测试改用 DATA-066。 | `subModules/lib_order/src/main/java/com/rhys/order/data/pending/KeystoreOrderPendingCipher.kt` | `OrderRepository` 默认 `cipher = KeystoreOrderPendingCipher()`（DATA-063）；未在纯 JVM 测试加载，真机密钥未覆盖。 |
| DATA-068 | `OrderPendingCodec` | 待确认请求的明文编解码；在落盘前必须整体加密。 | `internal object`，仅 `lib_order` 模块内可用。格式首行 `ORDER_PENDING_V1`，第二行 `createdAt`，第三行 URL 编码后的备注，之后每行 `recipeId,quantity`；URL 编码处理任意备注字符，避免依赖 JSON 或分隔符转义。解码要求至少 3 行、头部/时间正确、备注可解码、每行两个正整数、至少一条明细，否则返回 null；调用方按不可读 pending 处理，不猜内容。`idempotencyKey` 不进入明文载荷，由 store 外层单独保存。 | `subModules/lib_order/src/main/java/com/rhys/order/data/pending/OrderPendingCodec.kt` | `OrderRepository.persistPending/readPending`（DATA-063）调用；`OrderRepositoryPendingTest`（TEST-033）覆盖备注不落明文、损坏数据不可读。 |
