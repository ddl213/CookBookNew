# 05-07 · 聊天加密与 Room 缓存

> 返回分类首页：[05-network-storage.md](../05-network-storage.md)。Repository 与领域模型见 [06-chat-repository.md](06-chat-repository.md)，账号隔离见 [08-chat-session.md](08-chat-session.md)。

**收录范围：**聊天字段加密契约、AES-256-GCM 实现、Android Keystore 密钥、三张 Room 表、DAO、数据库单例、DTO/实体映射。

**索引原则：**只加密用户可见文本；解密失败只能展示安全占位；禁止明文落盘；schema 变更必须新增 Migration，不得破坏性迁移。

| DATA-043 | `ChatCipher`、`ChatDecryption`、`ChatCipherException`、`UNAVAILABLE_TEXT` | 聊天本地缓存字段加密契约；所有聊天正文、昵称、头像、会话预览、通知标题/正文落盘前必须经本接口。 | 只加密用户可见文本，ID、时间、类型、状态保持明文以支持查询与排序。`encrypt` 必须返回密文，失败抛 `ChatCipherException`，禁止回退明文；`decrypt` 任何失败（密钥失效、损坏、版本不支持）都返回 `ChatDecryption.Unavailable`，由调用方展示 `UNAVAILABLE_TEXT`（`[内容不可用]`），不得崩溃或展示原文。新增加密实现需保持相同失败语义；异常 message 可展示且不得包含明文。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/crypto/ChatCipher.kt` | `ChatEntityMapper`（DATA-049）读写加解密；默认 `KeystoreChatCipher`（DATA-045）与测试 `AesGcmChatCipher`（DATA-044）；`ChatRepositoryStorageTest`（TEST-023）覆盖加密落盘、密钥错误占位与加密失败不落库。 |
| DATA-044 | `AesGcmChatCipher` | AES-256-GCM 聊天字段加密实现；测试用 JVM 密钥与 Keystore 实现共用。 | 转换 `AES/GCM/NoPadding`、128-bit tag，每次加密随机 IV；密文格式固定为 `v1:<base64 iv>:<base64 ciphertext>`（ciphertext 含 tag）。密钥由构造参数 `keyProvider: () -> SecretKey` 提供。解密要求 3 段且版本为 `v1`、IV 非空、payload 不短于 16 字节；否则返回 `Unavailable`，不抛异常。空明文可正常加密并解出空串；篡改、不同密钥、未知版本均不可用。加密异常转 `ChatCipherException`，不返回明文。JVM 单测需自行生成 AES 密钥（Android Keystore 在纯 JVM 不可用）。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/crypto/AesGcmChatCipher.kt` | `KeystoreChatCipher` 委托本实现（DATA-045）；`ChatTestSupport.newTestCipher()`（TEST-026）用于测试；`AesGcmChatCipherTest`（TEST-024）覆盖随机 IV、篡改、空明文、不同密钥。 |
| DATA-045 | `KeystoreChatCipher` | 生产默认聊天加密：Android Keystore 保存 AES-256 密钥。 | 默认别名 `cookbook_chat_v1`，首次使用时在 `AndroidKeyStore` 生成 AES-256-GCM 密钥并缓存；进程级锁 + double-check 保证并发首次只生成一把密钥。密钥不可用（被系统清除、Keystore 缺失）时加密抛 `ChatCipherException`，解密返回 `Unavailable`，绝不回退明文。别名变更或密钥丢失会导致旧密文永久不可解；不要在业务中随意更换别名。依赖 Android 运行时，纯 JVM 测试改用 DATA-044。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/crypto/KeystoreChatCipher.kt` | `ChatRepository` 默认 `cipher = KeystoreChatCipher()`（DATA-039）；`ChatCipher` 契约见 DATA-043。 |
| DATA-046 | `ChatConversationEntity`、`ChatMessageEntity`、`ChatNotificationEntity`（三张 Room 表） | 加密聊天本地缓存表结构：会话、消息、预订通知。 | 表名 `chat_conversations`/`chat_messages`/`chat_notifications`。会话主键 `(ownerUserId, conversationId)`，索引 `(ownerUserId, updatedAtMillis)`；消息主键 `(ownerUserId, clientMessageId)`（`clientMessageId` 为幂等键，服务端缺失时用 `server:<id>`），索引 `(ownerUserId, conversationId, createdAtMillis)` 与 `(ownerUserId, serverId)`；通知主键 `(ownerUserId, notificationId)`，索引 `(ownerUserId, createdAtMillis)`。用户可见文本列均以 `*Cipher` 保存，ID/时间/类型/状态明文。主键必须包含 owner，禁止设计跨账号唯一主键；schema 变化必须新增 Migration。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/local/ChatEntities.kt` | `ChatDao`（DATA-047）、`ChatDatabase`（DATA-048）、`ChatEntityMapper`（DATA-049）使用；`ChatRepositoryStorageTest`（TEST-023）验证账号隔离与 upsert 去重。 |
| DATA-047 | `ChatDao` | 聊天本地缓存 DAO；所有读写必须带 `ownerUserId`。 | `@Dao abstract class`；`@Upsert` 覆盖单个/批量会话、消息、通知；观察查询按 owner 过滤并稳定排序（会话 updatedAt 倒序、消息 createdAt 升序、通知 createdAt 倒序）；`findConversation/findMessage`、`updateMessageStatus`、`updateConversationPreview`、三个 `count*` 均要求 owner。`deleteAllMessages/Conversations/Notifications` 与 `@Transaction clearAll()` 是唯一允许跨 owner 的写操作，只用于退出登录/切换账号，不得暴露给页面做局部清理。不要新增不带 owner 的读取入口。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/local/ChatDao.kt` | `ChatRepository` 全部本地读写（DATA-039）；`ChatSessionGuard` 调用 `clearAll`（DATA-051）；测试见 TEST-023/TEST-025。 |
| DATA-048 | `ChatDatabase`、`ChatDatabaseProvider` | 加密聊天缓存数据库与生产单例；提供测试用 in-memory 构建。 | `@Database` 三张实体、`version=1`、`exportSchema=false`，库名 `cookbook_chat.db`；`build(context)` 使用 `Room.databaseBuilder`，当前无 Migration、无 `fallbackToDestructiveMigration`。任何 schema 变更必须新增 Migration，破坏性迁移会永久丢失已加密聊天记录。`buildInMemory(context)` 用于单测（`allowMainThreadQueries`），不得用于生产。`ChatDatabaseProvider.get()` 首次访问时用 `AppHelper.application` 创建进程单例；`resetForTests` 为 internal 测试清理入口。应用启动前不会初始化。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/local/ChatDatabase.kt` | `ChatRepository` 默认数据库 provider（DATA-039）；`ChatSessionGuard.start(context)` 传入 application context（DATA-051）；测试见 TEST-023/TEST-025。 |
| DATA-049 | `ChatEntityMapper` | DTO/领域模型与 Room 实体互转；写入加密、读取解密。 | `internal class`，仅 `lib_chat` 模块内可用；不做线程切换，调用方负责 IO。会话映射在 `existing` 存在时合并且**禁止回退**：peer/最后消息/updatedAt 缺省时保留本地值，避免稀疏 refresh 清空昵称/头像/最后消息；本地最后消息时间晚于 DTO 时保留本地预览与时间，防止列表旧快照覆盖详情页刚发送的内容；`updatedAtMillis` 取 `max(existing.updatedAt, dto.updatedAt, 最后消息时间)`，`updatedAtRaw` 与胜出时间一致。最后消息预览/时间仅在 DTO 时间不早于本地已存时间时更新（同时间允许覆盖）；peer 昵称/头像在 DTO 非空时更新，缺省保留本地。要求会话 id、通知 id、DTO conversationId 为正。消息映射写入 `contentCipher`，解密失败统一 `UNAVAILABLE_TEXT`，null 字段保持 null；通知标题/正文加密。不要在模块外复制映射逻辑或绕过加密直接构造实体。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/local/ChatEntityMapper.kt` | `ChatRepository`（DATA-039）唯一使用方；加密契约见 DATA-043，表结构见 DATA-046；`ChatRepositoryStorageTest`（TEST-023，19 例）覆盖稀疏会话保留、较新本地预览不被刷新回退与解密失败占位。 |
