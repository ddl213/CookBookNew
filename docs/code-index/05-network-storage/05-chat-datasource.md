# 05-05 · 可替换聊天数据源

> 返回分类首页：[05-network-storage.md](../05-network-storage.md)。聊天接口与 DTO 见 [04-chat-network.md](04-chat-network.md)，Repository 与本地缓存见 [06-chat-repository.md](06-chat-repository.md)。

**收录范围：**`ChatDataSource` 可替换边界、构建期数据源配置、Remote/Mock 实现、实时消息扩展点。

**索引原则：**Mock 只用于本地开发与验收，必须明确标识，不得当作真实同步；实时源本期仅预留接口，不得伪造已连接。

| DATA-034 | `ChatDataSource`（接口）及 companion 归一化函数 | 聊天与通知的可替换数据源边界；页面/Repository 只依赖本接口，不直接依赖 Retrofit。 | 所有方法 `suspend`；`isMock` 必须由 UI 用于标识演示模式。`DEFAULT_LIMIT=20`、`MAX_LIMIT=50`、`MAX_MESSAGE_LENGTH=2000`；`normalizedLimit` 限制 1..50；`normalizedCursor` trim 后空白转 null；`normalizedClientMessageId` 要求非空白；`normalizedContent` trim 后要求 1..2000 字，违规抛 `IllegalArgumentException`。客户端校验不替代服务端好友关系、参与方与幂等判定。新增数据源实现须保持 `sendMessage` 对同一 `clientMessageId` 返回同一条消息。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/ChatDataSource.kt` | `RemoteChatDataSource`（DATA-036）与 `MockChatDataSource`（DATA-037）实现；`ChatRepository`（DATA-039）调用归一化；`MockChatDataSourceTest`（TEST-021）覆盖空白/超长拒绝。 |

| DATA-037 | `MockChatDataSource`、`ChatMockOperation`、`ChatMockFailure` | 内存版聊天数据源，供本地开发、演示与自动化验收；可注入延迟与失败验证发送中/失败/重试。 | `isMock=true`；数据仅存在内存，发送成功不代表服务端同步成功，UI 必须展示演示标识。构造参数：`localUserId`（默认 1）、`latencyMillis`、`failure`、`now`、`initialNotifications`；运行期可 `setLatencyMillis`/`setFailure` 模拟网络恢复。`openConversation` 对同一 peer 幂等，且会话 ID **跨 Mock 实例稳定**：演示对方固定返回 101，其他 peer 返回 `MOCK_CONVERSATION_BASE_ID + peerUserId`（1000+peer，peer 上限 `MAX_MOCK_PEER_ID=1,000,000`），不使用自增序号。新 Mock 实例遇到 Room 中已存在的稳定会话 ID 时通过 `ensureConversation` 按同一区间惰性恢复（演示会话缺失则重新播种）；仅 `1000+peerUserId` 区间内可惰性创建，其他未知/越界 ID 仍返回 `CHAT_NOT_FOUND`，不把任意小 ID 当合法会话。`sendMessage` 按 `clientMessageId` 幂等且不因重复提交新增记录；游标编码“排序键 + id”，按 updatedAt/createdAt 而非 id 推进，避免重复/遗漏。演示会话 101、对方 2、初始消息 3 条；当本地用户与演示对方冲突时自动顺延对方 id，但仍映射到演示会话 101。不得用于正式环境或作为后端契约证据。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/MockChatDataSource.kt` | `ChatDataSourceConfig` 的 mock 工厂默认创建（DATA-035）；`MockChatDataSourceTest`（TEST-021，16 例）覆盖演示数据、幂等、跨实例稳定会话 ID、新实例惰性恢复、越界 ID 404、分页、失败注入与身份冲突；`ChatRepositoryStorageTest`（TEST-023）覆盖延迟/失败经 Repository 后重试。 |
| DATA-038 | `ChatRealtimeSource`、`ChatRealtimeState`、`ChatRealtimeEvent`、`UnavailableChatRealtimeSource` | 实时消息扩展点；后端 WebSocket 就绪前明确返回不可用。 | 接口只定义 `connectionState`、`events`、`connect()`、`disconnect()`；状态 `UNAVAILABLE/DISCONNECTED/CONNECTING/CONNECTED`，事件只有 `MessageCreated`/`NotificationCreated`。默认实现 `UnavailableChatRealtimeSource` 固定 `UNAVAILABLE`、事件流为空、连接/断开为空操作。页面必须把 `UNAVAILABLE` 展示为“实时消息暂不可用”，不得伪造已连接或已接收；新增实现需自行定义重连、去重与生命周期，本期不提供。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/ChatRealtimeSource.kt` | `ChatRepository` 默认 `realtimeSource = UnavailableChatRealtimeSource()`（DATA-039）；`ChatRepositoryTest`（TEST-022）断言默认状态不可用且事件为空。 |
