# 05-09 · 订单网络接口、DTO 与错误映射

> 返回分类首页：[05-network-storage.md](../05-network-storage.md)。共享 `ApiClient`/鉴权见 [01-foundation-auth.md](01-foundation-auth.md)，订单数据源见 [10-order-datasource.md](10-order-datasource.md)，Repository 与待确认存储见 [11-order-repository-pending.md](11-order-repository-pending.md)。

**收录范围：**好友免费预订与双向订单的 Retrofit 接口、订单 DTO/状态/动作常量、订单错误映射、构建期数据源配置、Mock 订单通知存储契约。

**索引原则：**参与方、动作权限、版本冲突与幂等最终由服务端判定；`status`/`allowedActions` 是字符串快照，未知值不得解析为枚举或默认放行；Mock 通知只用于演示。

| ID | 类 / API / 资源入口 | 用途与优先复用场景 | 调用方式、前提和限制 | 定义文件（项目相对路径） | 真实调用位置 / 核查证据 |
| --- | --- | --- | --- | --- | --- |
| DATA-052 | `OrderApi.createOrder/listOrders/getOrder/actOnItem/cancelOrder`（suspend） | 好友免费预订与买卖双方订单的创建、分页、详情、明细动作与整单取消；新增订单请求优先复用本接口。 | Retrofit `suspend`，必须协程调用；baseUrl 已含 `/api/v1/`，路径为 `orders`、`orders/{orderId}`、`orders/{orderId}/items/{itemId}/{action}`、`orders/{orderId}/cancel`。全部需要登录并复用 DATA-004 的 token 拦截器。`createOrder` 必须传 `Idempotency-Key`（1～200 字符），同键同内容重放返回原订单，同键不同内容返回 409 `IDEMPOTENCY_KEY_REUSED`。`listOrders` 的 `role` 为 `buyer`/`seller`，`status` 筛选整单汇总状态，返回 DATA-016 `PageResponse<OrderDto>`；`getOrder` 对第三方返回 404；`actOnItem` 的 `action` 仅 accept/reject/ready/cancel/complete；明细动作与整单取消都带 `ExpectedVersionBody`，版本冲突原样上抛。客户端不得据此推断权限或跳过服务端校验。 | `subModules/lib_network/src/main/java/com/example/network/api/OrderApi.kt` | `RemoteOrderDataSource`（DATA-058）调用全部方法；`ApiClient.orderApi`（DATA-004）创建实例；DTO 见 DATA-053，错误映射见 DATA-054。 |
| DATA-053 | `OrderDto`、`OrderPartyDto`、`OrderItemDto`、`OrderRecipeDto`、`OrderItemCountsDto`、`CreateOrderBody`、`CreateOrderItem`、`ExpectedVersionBody`、`OrderStatus`、`OrderAction` | 订单响应、参与方/菜谱快照、计数、创建/版本请求体与状态/动作常量。 | `OrderDto(id,status,version,note?,buyer,seller,items,itemCounts,totalQuantity,allowedActions,createdAt?,updatedAt?)`；`OrderPartyDto` 提供 `displayName`（昵称空回退用户名），名称是下单时快照。`OrderItemDto` 含 `recipe`、`quantity`、`status`、`version`、`allowedActions`；`OrderRecipeDto.id` 可空、`imageUrl` 可为空串，缺图由 UI 占位。`OrderItemCountsDto` 各状态计数与 `total` 缺省为 0，总份数另看 `totalQuantity`。`CreateOrderBody(items, note?)`，Gson 默认省略 null note；`CreateOrderItem(recipeId, quantity)`；`ExpectedVersionBody(expectedVersion)`。`OrderStatus` 明细六态 + 整单 `CLOSED`，提供 `isKnown/isKnownItemStatus/isTerminalItemStatus`；`OrderAction` 明细动作 + 仅订单级 `cancelAll`，`ITEM_ACTIONS` 不含 `cancelAll`。所有比较用字符串；未知状态/动作保留原值，禁止 `valueOf` 或默认放行。 | `subModules/lib_network/src/main/java/com/example/network/bean/OrderDto.kt` | `OrderApi`（DATA-052）请求/响应类型；`OrderDataSource`/`RemoteOrderDataSource`/`MockOrderDataSource`/`OrderRepository`（DATA-057～DATA-063）使用；`MockOrderDataSourceTest`（TEST-032）覆盖状态/动作/计数。 |
| DATA-054 | `OrderErrorMapper.map` | 把订单 HTTP/网络异常转换为可展示 `AuthException`，统一订单业务码与状态码文案。 | 公开 `object`，`lib_order` 可直接调用；`map(throwable, unauthorizedMessage)` 对已是 `AuthException` 原样返回，`HttpException` 解析 DATA-008 错误体，`IOException` → `NETWORK_ERROR`，其他 → `UNKNOWN_ERROR`。业务码：`VALIDATION_ERROR`、`MIXED_SELLERS`、`CANNOT_ORDER_OWN_RECIPE`、`NOT_FRIENDS`、`FORBIDDEN_ORDER_ACTION`、`RECIPE_NOT_FOUND`、`ORDER_NOT_FOUND`、`ORDER_ITEM_NOT_FOUND`、`IDEMPOTENCY_KEY_REUSED`、`ORDER_VERSION_CONFLICT`、`INVALID_ORDER_ITEM_STATUS`、`ORDER_NOT_CANCELLABLE`；HTTP 401 用调用方文案，400/403/404/409/422/429/>=500 有回退文案。不记录 token、订单备注、请求体或响应全文；文案已是用户可读，页面直接使用 `message`。不做重试或请求去重。 | `subModules/lib_network/src/main/java/com/example/network/OrderErrorMapper.kt` | `RemoteOrderDataSource.call`（DATA-058）调用；`OrderErrorMapperTest`（TEST-030，20 例）覆盖业务码、HTTP 回退、IO/未知异常与既有 `AuthException`。 |
| DATA-055 | `OrderDataSourceConfig`、`OrderDataSourceKind`、`OrderDataSourceResolution` | 订单数据源的构建期配置解析；`lib_order` 与后续通知适配统一读取，避免各自解析 `BuildConfig`。 | `resolve(raw)` trim + 小写：`mock`/`remote` 为合法值；null、空白或未知值回退 `REMOTE` 并标记 `fallback=true`，同时保留 `rawValue` 供工厂告警。`current()` 读取 `BuildConfig.ORDER_DATA_SOURCE`；Gradle 属性 `orderDataSource` 在构建期写入，**debug/release 默认都是 remote**，`-PorderDataSource=mock` 才启用演示模式（DEP-008）。不使用 `chatDataSource` 作为订单默认值；服务地址统一复用 DATA-003 `NetworkConfig.baseUrl`。枚举值 `MOCK`/`REMOTE`。 | `subModules/lib_network/src/main/java/com/example/network/order/OrderDataSourceConfig.kt` | `OrderDataSourceFactory`（DATA-061）默认读取 `current()`；`OrderDataSourceConfigTest`（TEST-031，7 例）覆盖大小写/空白/非法回退/BuildConfig；构建字段见 DEP-008。 |
| DATA-056 | `OrderNotificationStore`、`InMemoryOrderNotificationStore`、`OrderNotificationType`、`OrderNotificationEvent/Actor/Item` | Mock 订单事件的内存共享存储与 schema 模型；`lib_order` 写入、`lib_chat` 通知适配读取，避免两个业务模块互相依赖。 | `OrderNotificationType` 固定六类：`order_created/order_accepted/order_rejected/order_ready/order_cancelled/order_completed`。事件含 `schemaVersion=2`、订单/接收方/操作者、明细前后状态与时间；`append` 由存储分配自增 ID（默认起点 `800_000`，与远端 ID 区间错开），`list(recipientId, limit)` 按倒序返回指定接收方，`limit` 夹取 1..200、默认 20，`recipientId<=0` 返回空，`clear` 清空并重置 ID。`InMemoryOrderNotificationStore.shared` 为进程级共享实例，测试可建独立实例。该存储**仅代表 Mock 事件**，不是后端通知、未读计数或已读状态来源；Remote 通知仍走 `NotificationApi`（DATA-030）并由 DATA-071 适配。通知页的“全部/仅订单”两种请求共用同一批 Mock 事件，不为 Mock 伪造 `recipe_share` 分享通知。 | `subModules/lib_network/src/main/java/com/example/network/order/OrderNotificationStore.kt` | `MockOrderDataSource`（DATA-059）在六类状态变更时写入；`OrderNotificationRepository.fetchMock`（DATA-071）按当前接收方读取并分页；`MockOrderDataSourceTest`（TEST-032）与 `OrderNotificationRepositoryTest`（TEST-039）覆盖接收方、操作者、明细与倒序分页。 |
