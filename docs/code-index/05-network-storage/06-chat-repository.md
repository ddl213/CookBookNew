# 05-06 · 聊天 Repository 与领域模型

> 返回分类首页：[05-network-storage.md](../05-network-storage.md)。数据源与配置见 [05-chat-datasource.md](05-chat-datasource.md)，加密与 Room 缓存见 [07-chat-crypto-room.md](07-chat-crypto-room.md)，账号隔离见 [08-chat-session.md](08-chat-session.md)。

**收录范围：**聊天数据访问层、解密后的领域模型、当前账号 owner 来源、聊天时间解析。

**索引原则：**未登录不得读写本地缓存；发送状态只表示本地 SENDING/SENT/FAILED，不代表服务端已读/送达；所有用户可见文本落盘前加密。

| DATA-039 | `ChatRepository` | 聊天数据访问层：远端/Mock 数据源 + 加密 Room 缓存；页面应经本类读写聊天，不直接访问 DAO、数据源或 Retrofit。 | 构造参数可注入 `ChatDataSource`、`ChatRealtimeSource`、数据库 provider、`ChatCipher`、`ChatOwnerProvider`、IO dispatcher、时钟与 `clientMessageId` 工厂；默认面向生产（DATA-035/045/048/041）。观察流 `observeConversations/observeMessages/observeNotifications` 必须登录：未登录直接发空列表，不打开数据库、不读取缓存；`observeMessages` 要求 conversationId>0。`refresh*`/`openConversation`/`sendMessage`/`retryMessage` 在未登录时抛 `AuthException(code=UNAUTHORIZED, httpStatus=401)`；远端结果落库前用 `ensureOwner` 复核，账号切换后拒绝旧 owner 写入。发送流程：先以 UUID `clientMessageId` 加密写入本地 `SENDING`，成功用同一主键更新为 `SENT`，失败标记 `FAILED` 并抛 DATA-033 可展示异常，绝不新增第二条；`senderId` 以已认证 owner 为准，忽略数据源返回的其他身份；协程取消时在 `NonCancellable` 中标记 FAILED 后原样重抛。`retryMessage` 先 `requireOwner`，在读取本地行前再次 `ensureOwner`（避免账号切换窗口读到旧账号消息）；复用原 `clientMessageId` 与已加密正文，本地缺失抛 `CHAT_MESSAGE_NOT_FOUND`(404)；若已 SENT 且已有 `serverId`，提前返回前**再复核一次 owner**，账号已切换时不得返回旧 owner 的已发送消息。远端历史按 `clientMessageId`（缺失时 `server:<id>`）upsert，保留本地 SENDING/FAILED 状态与正文；会话稀疏刷新保留已有昵称/头像/最后消息；分页拉取不删除已缓存内容。本地加密失败抛 `ChatCipherException` 且不写库；解密失败以安全占位展示。无统一重试队列、请求去重（除 clientMessageId）、乐观已读或推送。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/ChatRepository.kt` | 实际消费方为 `ChatFragment`（会话列表/通知入口）、`ChatNotificationsFragment`（独立通知列表）、`ChatDetailFragment`（消息历史/发送/重试），见 ARCH-017；测试为 `ChatRepositoryTest`（TEST-022）、`ChatRepositoryStorageTest`（TEST-023）、`ChatSessionGuardTest`（TEST-025）。依赖 DATA-034～DATA-038、DATA-040～DATA-051。 |
| DATA-040 | `ChatConversation`、`ChatMessage`、`ChatMessageStatus`、`ChatNotification` | 解密后的聊天领域模型，供页面展示与本地排序。 | 与网络 DTO 分离；`ChatConversation` 含 peerId/peerNickname?/peerAvatar?/lastMessagePreview?/updatedAt(ms)/updatedAtRaw?；`ChatMessage` 含 serverId?/clientMessageId/conversationId/senderId/receiverId?/content/createdAt(ms)/createdAtRaw?/status；`ChatNotification` 含 id/type/title/body/orderId?/createdAt(ms)/createdAtRaw?。`ChatMessageStatus` 仅 SENDING/SENT/FAILED，`fromStored` 遇未知历史值按 SENT 处理，避免把服务端消息误报失败；不含已读/送达字段，不得自行推断。解密失败内容为 DATA-043 的安全占位；时间字符串只用于排查/展示，排序用毫秒。 | `subModules/lib_chat/src/main/java/com/rhys/chat/domain/ChatModels.kt` | `ChatRepository`（DATA-039）返回；`ChatEntityMapper`（DATA-049）映射；`ChatRepositoryStorageTest`（TEST-023）断言状态与占位。 |
| DATA-041 | `ChatOwnerProvider`、`SessionChatOwnerProvider` | 聊天缓存 owner 来源；决定当前登录用户是否可读写本地聊天数据。 | `fun interface`，`currentOwnerId(): Long?`；生产默认实现只从 `SessionManager.state` 的 `AuthState.LoggedIn.user.id` 取值，`Unknown`/`LoggedOut` 返回 null。调用方不得在 null 时读写缓存或回退到其他用户；测试可注入固定/可变 owner 验证账号隔离。仅用于账号隔离，不保存 token 或聊天内容。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/ChatOwnerProvider.kt` | `ChatRepository` 默认 ownerProvider（DATA-039）；`ChatDataSourceConfig` 的 Mock 工厂读取（DATA-035）；测试注入见 TEST-023/TEST-025。 |
| DATA-042 | `ChatTime.parseMillis/formatIso` | 解析后端 ISO-8601 时间并生成本地发送时间，供加密缓存稳定排序。 | `parseMillis` 支持 4 种带/不带毫秒、带 `XXX` 或 `Z` 的 ISO 格式；输入 blank 或解析失败返回 0，不抛异常，避免服务端时间异常阻断其余字段落库；`Z` 格式按 UTC 解析。`formatIso` 输出 UTC `yyyy-MM-dd'T'HH:mm:ss.SSS'Z'`。仅处理时间字符串，不校验业务时序；DAO 排序见 DATA-047。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/ChatTime.kt` | `ChatRepository` 生成 SENDING 时间（DATA-039）；`ChatEntityMapper`（DATA-049）解析 DTO 时间；`MockChatDataSource` 使用同类 ISO 格式。 |
