# 05-04 · 聊天与通知网络接口

> 返回分类首页：[05-network-storage.md](../05-network-storage.md)。基础网络/认证见 [01-foundation-auth.md](01-foundation-auth.md)，可替换数据源见 [05-chat-datasource.md](05-chat-datasource.md)，Repository 与本地存储见 [06-chat-repository.md](06-chat-repository.md)，订单通知存储见 [09-order-network.md](09-order-network.md)。

**收录范围：**好友一对一聊天与预订通知的 Retrofit 接口、游标/页码分页、聊天/通知 DTO、聊天错误映射，以及 `lib_chat` 的订单通知 DTO 适配、纯映射与分页 Repository。

**索引原则：**全部接口需要登录且以后端权限判定为准；游标对客户端不透明；本期无已读/送达状态，客户端不得推断；通知 `read/readAt` 只随响应传输，不展示、不缓存、不据此推断未读。P07 通知游标接口为遗留能力，后端只接受页码，禁止透传 `cursor`。

| DATA-029 | `ChatApi.listConversations/openConversation/listMessages/sendMessage`（suspend） | 好友一对一文字聊天的会话列表、打开/创建会话、历史消息与发送接口；新增聊天请求优先复用本接口。 | Retrofit `suspend`，必须协程调用；baseUrl 已含 `/api/v1/`，路径为 `chat/conversations`、`chat/conversations/{conversationId}/messages`。全部需要登录，由 DATA-004 附加 token；好友关系与会话参与方由后端校验，客户端隐藏入口不构成权限控制。`listConversations` 按 updatedAt 倒序，`cursor` 为空为第一页；`listMessages` 按 createdAt 升序，`before` 指向更早一页；`sendMessage` 服务端按 `clientMessageId` 幂等，重复提交返回同一条记录。`limit`/`cursor` 由 DATA-034 归一化；返回 DATA-031；非 2xx 由 DATA-033 映射。 | `subModules/lib_network/src/main/java/com/example/network/api/ChatApi.kt` | `RemoteChatDataSource`（DATA-036）调用四个方法；`ApiClient.chatApi`（DATA-004）创建实例；`CursorPageTest`（TEST-019）覆盖消息页 JSON 解析。 |
| DATA-030 | `NotificationApi.listNotifications`（P07 遗留）、`NotificationApi.listOrderNotifications`（suspend） | 消息列表中的独立通知接口：旧 P07 游标接口仅供遗留代码，**不得用于新功能**；P08 通知页使用 `category=order` 页码接口。 | Retrofit `suspend`，必须协程调用；baseUrl 已含 `/api/v1/`，路径均为 `notifications`；需要登录。`listNotifications(limit, cursor)` 返回 DATA-031 `CursorPage<ChatNotificationDto>`，`limit`/`cursor` 由 DATA-034 归一化，原用于旧预订通知。**遗留风险：后端 `GET /notifications` 当前只识别 `page/pageSize`，不识别 `limit/cursor`，该接口不会真正透传游标，返回 `nextCursor` 为 null；未来若复用必须在数据源/客户端内部把游标转换为页码后再请求，不得把 cursor 直接透传给后端。**`listOrderNotifications(category="order", page, pageSize)` 返回 DATA-069 `PageResponse<OrderNotificationDto>`，调用方必须先归一化 `page>=1`、`pageSize=1..50`，服务端按类别过滤后可能出现空页。两者均无未读计数/已读回执，`read/readAt` 不得用于客户端推断。非 2xx 由 DATA-033 映射；不要与聊天会话列表混为同一接口。 | `subModules/lib_network/src/main/java/com/example/network/api/NotificationApi.kt` | `RemoteChatDataSource.listNotifications`（DATA-036）是旧接口的 main 包装调用；`ChatRepository.refreshNotifications`（DATA-039）**未发现 main 页面调用方**，仅定义与测试使用；P08 通知页经 DATA-071 调用新接口（ARCH-017）；`ApiClient.notificationApi`（DATA-004）创建实例。 |
| DATA-031 | `CursorPage<T>`、`hasMore` | 聊天/通知统一游标分页响应载体 `{ items, nextCursor }`。 | `items` 默认空列表；`nextCursor` 为 null 或空白时 `hasMore=false`。游标对客户端不透明，必须原样回传下一次请求，不能解析、拼接或按 id 自造；服务端仍为分页与排序的最终判定方。Gson 缺省字段按 data class 默认值处理（`missing fields use safe defaults`）。不要套用 DATA-016 的页码分页。 | `subModules/lib_network/src/main/java/com/example/network/bean/CursorPage.kt` | `ChatApi`/`NotificationApi` 返回类型；`ChatDataSource`（DATA-034）与 `ChatRepository`（DATA-039）透传；`CursorPageTest`（TEST-019）覆盖 items/nextCursor 与缺省值。 |
| DATA-032 | `ChatConversationDto`、`ChatMessageDto`、`SendChatMessageBody`、`OpenChatConversationBody`、`ChatNotificationDto` | 聊天会话、一对一消息、发送/打开会话请求体与预订通知的传输模型。 | `ChatConversationDto(id, peer: UserDto?, lastMessage?, updatedAt?)`；`ChatMessageDto(id, conversationId, clientMessageId, senderId, receiverId?, type=TEXT, content, createdAt?)`；`SendChatMessageBody(clientMessageId, type=TEXT, content)`；`OpenChatConversationBody(peerUserId)`；`ChatNotificationDto(id, type=RESERVATION, title, body, orderId?, createdAt?)`。字段带默认值以容忍后端缺省；时间均为 ISO-8601 字符串，本地毫秒解析见 DATA-042。本期契约不含已读/送达/发送状态，客户端不得自行推断服务端已读；`clientMessageId` 是幂等键，重试必须保持同一值。展示前不要与 DATA-014 用户 DTO 混用；`peer` 可空，页面需安全占位。 | `subModules/lib_network/src/main/java/com/example/network/bean/ChatMessageDto.kt` | 同目录 `ChatConversationDto.kt`、`ChatNotificationDto.kt`；`ChatApi`/`NotificationApi` 与 `ChatRepository`（DATA-039）使用；`CursorPageTest`（TEST-019）覆盖字段解析与缺省。 |
| DATA-033 | `ChatErrorMapper.map` | 把聊天/通知网络与 HTTP 异常转换为可展示 `AuthException`，统一聊天业务码与状态码文案。 | 公开 `object`（不同于 DATA-018 的 `internal`），`lib_chat` 可直接调用；`map(throwable, unauthorizedMessage)` 对已是 `AuthException` 原样返回，`HttpException` 解析 DATA-008 错误体，`IOException` → `NETWORK_ERROR`，其他 → `UNKNOWN_ERROR`。业务码：`NOT_FRIENDS`、`CHAT_FORBIDDEN`、`CHAT_NOT_FOUND`、`VALIDATION_ERROR`、`FORBIDDEN`；HTTP：401 用调用方文案，400/422 内容不合法，403 无权限，404 不存在，409 重复提交，429 频繁，>=500 服务不可用。不记录 token、消息正文或会话内容；文案已是用户可读，页面直接使用 `message`。无重试与请求去重。 | `subModules/lib_network/src/main/java/com/example/network/ChatErrorMapper.kt` | `RemoteChatDataSource.callChatApi`（DATA-036）与 `ChatRepository.deliver`（DATA-039）调用；`ChatErrorMapperTest`（TEST-018）覆盖 401/403/404/400/422/429/500/IOException。 |
| DATA-069 | `OrderNotificationDto`、`OrderNotificationPayloadDto`、`OrderNotificationActorDto`、`OrderNotificationItemDto`、`OrderNotificationBuyerDto` | `GET notifications?category=order` 的订单通知传输模型，同时兼容 P07 单菜品旧通知；新增订单通知解析优先复用本组 DTO。 | `OrderNotificationDto(id=0,type="",payload?,read=false,readAt?,createdAt?,title?,body?,orderId?)`；payload 含 `schemaVersion/orderId/orderStatus/actor/items` 与旧字段 `recipeId/recipeName/status/buyer/title/body`；actor 为 `id/nickname`；item 为 `itemId/recipeId?/recipeName/quantity/fromStatus?/toStatus`，菜谱删除后 `recipeId` 可空；buyer 提供 `displayName=nickname.ifBlank{username}`。字段均有默认值以容忍 Gson 缺省；`read/readAt` 仅传输，不展示、不缓存、不推断未读/已读。所有 `type/status` 保留原始字符串，不转枚举、不默认放行；时间 ISO-8601 由 DATA-042 解析。不要与 DATA-032 聊天 DTO 混用。 | `subModules/lib_network/src/main/java/com/example/network/bean/OrderNotificationDto.kt` | `NotificationApi.listOrderNotifications`（DATA-030）返回类型；`OrderNotificationRepository.fetchRemote`（DATA-071）与 `OrderNotificationMapper`（DATA-070）消费；`OrderNotificationMapperTest`/`OrderNotificationRepositoryTest`（TEST-038/TEST-039）覆盖字段与映射。 |
| DATA-070 | `OrderNotificationMapper.map(dto)`、`map(event)` | 把订单通知 DTO 或 Mock 事件转换为 `lib_chat` 现有 `ChatNotification`，统一六类订单文案、旧 payload 回退与明细摘要；页面展示优先复用。 | `internal object`，**仅 `lib_chat` 模块内可见**；纯函数，不访问网络、数据库或 Store。`id<=0` 返回 null；`title/body` 优先级：顶层显式值 → payload 旧值 → 按 type 生成；六类 `order_created/accepted/rejected/ready/cancelled/completed` 有固定中文，未知 type 用“预订通知/订单状态有更新”；actor 优先 `payload.actor.nickname`，其次旧 buyer 昵称/用户名，再回退“好友”；明细按“菜名×数量”最多展示 2 项并追加“等”，无明细回退旧 `recipeName`，仍空用“你的菜品”；`orderId` 先取顶层正数再取 payload 正数；`createdAt` 原文保留并经 DATA-042 转毫秒，缺失为 0；`read/readAt` 不参与映射。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/OrderNotificationMapper.kt` | `OrderNotificationRepository.fetchMock/fetchRemote`（DATA-071）调用；`ChatNotificationsFragment` 通过 Repository 结果展示（ARCH-017）；`OrderNotificationMapperTest`（TEST-038，10 例）覆盖六类、旧 payload、缺省、非法 id、orderId/时间优先级与明细截断。 |
| DATA-071 | `OrderNotificationRepository`（`fetch`、`cached`、`invalidate`、`isMock`） | 预订通知页的数据访问层：按订单数据源配置读取 Remote/Mock 通知，提供页码分页、页缓存与账号/环境隔离；新增订单通知页优先复用。 | 构造函数可注入 `dataSourceKind`、`NotificationApi`、`OrderNotificationStore`、`ownerProvider`、`baseUrlProvider`；默认 `OrderDataSourceConfig.current().kind`、`ApiClient.notificationApi`、`InMemoryOrderNotificationStore.shared`、`SessionManager` 当前用户与 `NetworkConfig.baseUrl`。**跟随订单配置，不使用 `chatDataSource`**。`fetch(page,pageSize)` 须协程调用：未登录抛 `UNAUTHORIZED`；`page` 夹取 `>=1`，`pageSize` 夹取 1..50（默认 20）；Remote 调 DATA-030 `category=order`，失败经 DATA-033 映射且**不回退 Mock**；Mock 读取当前接收方事件（最多 200 条），按 `createdAt`/`id` 倒序内存分页。缓存按 ownerId、Mock/Remote、baseUrl 三元组隔离，作用域变化清空；响应返回后再核对 owner/作用域，不一致抛登录变更错误；`cached` 命中需 pageSize 一致。本期无未读/已读、红点、推送，不新增订单通知 Room 表，也不改动聊天 Room 缓存。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/OrderNotificationRepository.kt` | `ChatNotificationsFragment.refreshFirstPage/loadMore`（ARCH-017）是唯一页面消费方；Mock 事件来源 DATA-056；`OrderNotificationRepositoryTest`（TEST-039，9 例）覆盖 Remote 分页/类别、Mock 接收方隔离与倒序、登录与错误、页码归一化、三重作用域缓存与空页。 |
