# 05-12 · 通知接口与订单通知适配

> 返回分类首页：[05-network-storage.md](../05-network-storage.md)。聊天接口与游标分页见 [04-chat-network.md](04-chat-network.md)，订单网络接口与 Mock 通知存储见 [09-order-network.md](09-order-network.md)，页面结构见 ARCH-017。

**收录范围：**`NotificationApi` 的订单/全部通知页码接口与 P07 遗留游标接口、订单通知 DTO（含 `recipe_share` 分享者快照）、纯映射，以及按请求范围隔离的通知 Repository。

**索引原则：**全部通知与仅订单是两条不同请求，客户端按 `type` 分支，不按标题文案推断；`read/readAt` 只随响应传输，不展示、不缓存、不据此推断未读；Mock 事件不为分享通知伪造数据；P07 游标接口禁止用于新功能。

| DATA-030 | `NotificationApi.listOrderNotifications`、`NotificationApi.listAllNotifications`、`NotificationApi.listNotifications`（P07 遗留） | 通知页分页接口：仅订单（`category=order`）、全部通知（不带 `category`，含 `recipe_share` 等非订单通知）与 P07 遗留游标接口；新增通知读取优先使用两个页码接口。 | Retrofit `suspend`，必须协程调用；baseUrl 已含 `/api/v1/`，路径均为 `notifications`；需要登录并复用 DATA-004 token。`listOrderNotifications(category="order", page, pageSize)` 与 `listAllNotifications(page, pageSize)` 均返回 DATA-069 `PageResponse<OrderNotificationDto>`；调用方必须先归一化 `page>=1`、`pageSize=1..50`。全部通知不带类别过滤，客户端必须按 `type` 区分订单/分享的展示与跳转。服务端分页/过滤后可能出现空页但仍有后续页，加载更多需自增页码跳过空页（页面最多连续跳 3 页）。`listNotifications(limit, cursor)` 为 P07 遗留：后端只识别 `page/pageSize`，`nextCursor` 恒为 null，**禁止用于新功能**；若复用必须在数据源/客户端内部把游标转换为页码。无未读计数/已读回执，`read/readAt` 不得用于客户端推断；非 2xx 由 DATA-033 映射；不要与聊天会话列表混为同一接口。 | `subModules/lib_network/src/main/java/com/example/network/api/NotificationApi.kt` | `OrderNotificationRepository.fetch/fetchAll`（DATA-071）分别调用两个页码接口；`ChatNotificationsFragment` 经 DATA-071 `fetchAll` 消费（ARCH-017）；`RemoteChatDataSource.listNotifications`（DATA-036）仅包装旧接口，无 main 页面调用方；`ApiClient.notificationApi`（DATA-004）创建实例；`OrderNotificationRepositoryTest`（TEST-039）断言全部通知请求不带 category。 |
| DATA-069 | `OrderNotificationDto`、`OrderNotificationPayloadDto`、`OrderNotificationActorDto`、`OrderNotificationItemDto`、`OrderNotificationBuyerDto`、`OrderNotificationFromUserDto` | `GET notifications`（订单/全部）的传输模型，兼容 P07 单菜品旧通知与 `recipe_share` 分享者快照；新增通知解析优先复用。 | `OrderNotificationDto(id=0,type="",payload?,read=false,readAt?,createdAt?,title?,body?,orderId?)`；payload 含 `schemaVersion/orderId/orderStatus/actor/items`、旧字段 `recipeId/recipeName/recipeImage/status/buyer/title/body` 与分享者 `fromUser`；actor 为 `id/nickname`；item 为 `itemId/recipeId?/recipeName/quantity/fromStatus?/toStatus`，菜谱删除后 `recipeId` 可空；buyer 与 fromUser 提供 `displayName = nickname.ifBlank { username }`。`recipe_share` 用 `fromUser` + `recipeId` + `recipeName` 生成分享通知；`recipeImage` 目前只解析保留，通知页未展示（main 无消费方）。字段均有默认值以容忍 Gson 缺省；`read/readAt` 仅传输；所有 `type/status` 保留原始字符串，不转枚举、不默认放行；时间 ISO-8601 由 DATA-042 解析。不要与 DATA-032 聊天 DTO 混用。 | `subModules/lib_network/src/main/java/com/example/network/bean/OrderNotificationDto.kt` | `NotificationApi`（DATA-030）返回类型；`OrderNotificationRepository.fetchRemote`（DATA-071）与 `OrderNotificationMapper`（DATA-070）消费；`OrderNotificationMapperTest`/`OrderNotificationRepositoryTest`（TEST-038/TEST-039）覆盖分享者、字段与映射。 |
| DATA-070 | `OrderNotificationMapper.map(dto)`、`map(event)` | 把订单通知 DTO 或 Mock 事件转换为 `lib_chat` `ChatNotification`：六类订单文案、旧 payload 回退、`recipe_share` 分享文案与菜谱 ID；页面展示优先复用。 | `internal object`，**仅 `lib_chat` 模块内可见**；纯函数，不访问网络、数据库或 Store。`id<=0` 返回 null。`type` 忽略大小写等于 `recipe_share` 时走分享分支：标题“菜谱分享”、正文“「分享者」分享了「菜名」”（昵称→用户名→“好友”，菜名为空→“菜谱”），`orderId` 固定 null、`recipeId` 取 payload 正数；显式 `title/body`（顶层→payload）仍优先。其余六类 `order_created/accepted/rejected/ready/cancelled/completed` 用固定中文，未知 type 用“预订通知/订单状态有更新”；actor 优先 `payload.actor.nickname`，其次旧 buyer 昵称/用户名，再回退“好友”；明细按“菜名×数量”最多 2 项并追加“等”，无明细回退旧 `recipeName`，仍空用“你的菜品”；`orderId` 先取顶层正数再取 payload 正数；`createdAt` 原文保留并经 DATA-042 转毫秒，缺失为 0；`read/readAt` 不参与映射。分享通知不伪造订单关联。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/OrderNotificationMapper.kt` | `OrderNotificationRepository.fetchMock/fetchRemote`（DATA-071）调用；`ChatNotificationsFragment` 经 Repository 结果展示并按 `orderId`/`recipeId` 跳转（ARCH-017）；`OrderNotificationMapperTest`（TEST-038，14 例）覆盖六类、旧 payload、分享四种分支、缺省、非法 id、orderId/时间优先级与明细截断。 |
| DATA-071 | `OrderNotificationRepository`（`fetch`、`fetchAll`、`cached`、`invalidate`、`isMock`）、`NotificationScope` | 通知页的数据访问层：按请求范围读取仅订单或全部通知，提供页码分页、页缓存与账号/环境/范围隔离；新增通知页优先复用。 | 构造函数可注入 `dataSourceKind`、`notificationApi`、`mockStore`、`ownerProvider`、`baseUrlProvider`；默认 `OrderDataSourceConfig.current().kind`、`ApiClient.notificationApi`、`InMemoryOrderNotificationStore.shared`、`SessionManager` 当前用户与 `NetworkConfig.baseUrl`。**跟随订单配置，不使用 `chatDataSource`**。`fetch(page,pageSize)` = `NotificationScope.ORDER`（Remote `category=order`）；`fetchAll(page,pageSize)` = `NotificationScope.ALL`（Remote 不带 `category`），均须协程调用；未登录抛 `UNAUTHORIZED`；`page` 夹取 `>=1`，`pageSize` 夹取 1..50（默认 20）。Remote 失败经 DATA-033 映射且**不回退 Mock**；Mock 读取当前接收方事件（最多 200 条）按 `createdAt`/`id` 倒序内存分页，**全部与仅订单共用同一批事件，不为 Mock 伪造分享通知**。缓存按 `ownerId`、Mock/Remote、`baseUrl`、`NotificationScope` 四元组隔离，账号、环境或范围变化清空；响应返回后再核对 owner/作用域，不一致抛登录变更错误；`cached(page,pageSize,notificationScope=ORDER)` 命中需 pageSize 一致。本期无未读/已读、红点、推送，不新增订单通知 Room 表，也不改动聊天 Room 缓存。 | `subModules/lib_chat/src/main/java/com/rhys/chat/data/OrderNotificationRepository.kt` | `ChatNotificationsFragment.refreshFirstPage/loadMore`（ARCH-017）调用 `fetchAll`，是唯一页面消费方；Mock 事件来源 DATA-056；`OrderNotificationRepositoryTest`（TEST-039，11 例）覆盖 Remote 分页/类别、全部通知不带 category 与分享映射、Mock 接收方隔离与倒序、登录与错误、页码归一化、四维作用域缓存（全部与仅订单互不复用）与空页。 |
