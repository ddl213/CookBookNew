# 03-01 · 列表、Adapter 与刷新

> 返回分类首页：[03-custom-views-ui.md](../03-custom-views-ui.md)

**收录范围：**RecyclerView 装饰、下拉刷新、Builder 式 Adapter、ViewPager2 FragmentAdapter、订单列表/详情页面内适配与动态动作按钮。

| ID | 类 / API / 资源入口 | 用途与优先复用场景 | 调用方式、前提和限制 | 定义文件（项目相对路径） | 真实调用位置 / 核查证据 |
| --- | --- | --- | --- | --- | --- |
| VIEW-001 | `RvDecoration` 及 `Builder` | 为普通列表和带刷新头的列表设置内容间距、分割线；刷新头不额外占装饰间距。 | `rv.addItemDecoration(RvDecoration.Builder().setVertical(6).setHorizontal(10).build())`；间距参数为 dp，可分别设置四边。跳过 `RefreshHeaderAdapter` 的间距与分割线，递归定位 `ConcatAdapter` 首个内容项。竖向 Grid 按实际 `SpanSizeLookup` 计算列间距和首内容行顶部间距；刷新头须占满一行（`RefreshRecyclerView` 自动处理），内容 span 必须在 `1..spanCount` 内。 | `subModules/lib_android_common/src/main/java/com/android/common/utils/RvDecoration.kt` | `CookBookChildFragment` 使用 `setVertical(6)`，未设置分割线；`CookBookDetailFragment` 评论列表与 `ShareFriendDialog` 好友列表使用 `setVertical(2)`；`IndexChildFragment` 使用普通间距。测试：`RvDecorationRefreshTest.kt` 覆盖默认头高 0、首内容 top 42、下拉复位、普通列表、Grid 整行头及多 span、跳过头部分割线。 |
| VIEW-002 | `RefreshRecyclerView`、`IRefreshHeader`、`RefreshHeaderView`、`RefreshHeaderAdapter` | 下拉刷新列表；刷新头默认零高，下拉显示，完成后收起。 | 通过 `buildRefreshAdapter<T>(header = true)` 或手动 `ConcatAdapter(RefreshHeaderAdapter(header), dataAdapter)` 接入；`setOnRefreshListener` 请求数据，完成后调用 `refreshComplete()`。仅支持竖向手势；`footer = true` 会抛异常；Grid 头自动占满一行；`refreshComplete` 前保持 `REFRESHING` 状态，期间不再触发新刷新。 | `subModules/lib_android_common/src/main/java/com/android/common/base/adapter/refresh/RefreshRecyclerView.kt` | `CookBookChildFragment` 使用 `buildRefreshAdapter(header = true)`，`setOnRefreshListener { loadFirstPage() }` 请求 `/recipes/mine`，完成后 `refreshComplete()`；测试：`RefreshRecyclerViewTest.kt`、`RefreshHeaderViewTest.kt` 覆盖慢拉、取消、Grid、换头、完成时序。 |
| VIEW-003 | `AdapterBuilder<T>`、`BaseAdapter`、`SingleAdapter`、`MutableAdapter`、`BaseViewHolder` | 通过 Builder 配置单/多布局、Diff、点击、空布局初始化；数据用 `submitList/addItems` 提交。 | 主线程使用；必须设置 `setDiff` 和 `setLayout`，`bind`/`bindMulti` 二选一；多布局需 `setViewTypeDelegate`，绑定按 `holder.localViewType` 区分布局；点击回调的 `position` 为数据 Adapter 本地下标；列表做浅快照，元素应不可变。 | `subModules/lib_android_common/src/main/java/com/android/common/base/adapter/AdapterBuilder.kt` | `IndexFragment`、`IndexChildFragment`、`CookBookChildFragment` 使用；测试：`AdapterBuilderTest.kt`、`BaseAdapterTest.kt` 覆盖配置顺序、多布局、快照、点击、payload、footer 拒绝。 |
| VIEW-004 | `CommonFragmentAdapter`、`TabInfo` | ViewPager2 的 FragmentStateAdapter；按标签列表创建 Fragment 并注入参数。 | `TabInfo` 默认通过 `Class.forName(fragmentFullName)` 反射得到 Fragment 类，要求传入完整类名且 Fragment 有无参构造；`bundle` 为空时注入 `KEY_BUNDLE_PAGE_ID = id`。`setNewData` 会清空并 `notifyDataSetChanged`。 | `subModules/lib_android_common/src/main/java/com/android/common/base/CommonFragmentAdapter.kt` | `HomeFragment` 与 `CookBookFragment` 构造 `TabInfo` 并设置 `vp.adapter`；`TabInfo.kt` 定义 `fragmentFullName` 与 `bundle`。 |
| VIEW-019 | `OrderFragment` 订单列表内联适配器（`OrderRow` + `OrderItemOrderBinding`） | 订单 Tab“我的订单/我的销售”双角色订单卡片列表：对方名称/角色、整单状态、菜品摘要、计数与状态分布、创建时间与首图；新增订单列表优先复用该绑定，不另建 Adapter。 | 页面内 `rvOrders.liner().buildAdapter<OrderRow>`，`setDiff(areItemsSame=order.id, areContentsSame=整行)`，`setLayout(OrderItemOrderBinding)`；`OrderRow(order, role)` 让角色参与内容比较，切换买家/卖家后会重新绑定对方名称；状态筛选 chip 由 `selectStatus()` 切换 `isSelected` 并重置分页（chip 与顺序当前由布局/`updateFilterUi()` 硬编码；BIZ-015 `FILTERS` 尚未被页面读取，仅单测校验）；`RvDecoration.Builder().setVertical(10)`；滚动到倒数第 2 项调用 `loadMore()`。展示文案/过滤/去重/时间均来自 BIZ-015；**未抽成跨模块 Adapter**，仅 `lib_order` 页面内可用；不在页面直接依赖 Retrofit/Mock。 | `subModules/lib_order/src/main/java/com/rhys/order/OrderFragment.kt` | `bindOrderList()` 配置 Diff/布局/绑定/点击与触底监听，`submitRows()` 提交带当前角色的行，`updateFilterUi()/selectStatus()/reloadForSelectionChange()` 维护状态筛选并重置分页；条目布局 `subModules/lib_order/src/main/res/layout/order_item_order.xml`，页面布局 `order_fragment_order.xml`；页面入口见 ARCH-020。 |
| VIEW-020 | `OrderDetailFragment` 详情明细与动态动作按钮（`renderItems`、`createActionButton`） | 订单详情按服务端 `allowedActions` 动态生成明细动作（接单/拒单/备货完成/取消/确认取货），并提供“取消整单”按钮与确认框；新增订单动作 UI 优先复用该模式。 | 明细通过 `OrderItemOrderDetailBinding.inflate` 加入 `llItems`，**不是 RecyclerView**；动作顺序与过滤来自 BIZ-015 `knownItemActions`，`cancelAll` 只在 `canCancelAll` 时展示为整单按钮；主/次动作分别使用 `order_bg_primary_button`/`order_bg_secondary_button`；动作提交使用明细/订单 `version`，版本冲突、状态不允许、不可取消或 404 提示后重新拉取，不自动换版本重试；确认框显示期间禁用动作。仅 `lib_order` 页面内使用，不推断服务端未返回的动作。 | `subModules/lib_order/src/main/java/com/rhys/order/ui/OrderDetailFragment.kt` | `renderItems()/createActionButton()/requestItemAction()/requestCancelAll()/submitItemAction()/submitCancelAll()`；布局 `subModules/lib_order/src/main/res/layout/order_fragment_order_detail.xml`、`order_item_order_detail.xml`；路由与参数见 ARCH-020，纯逻辑见 BIZ-015。 |
