# P00 · 需求基线与实施边界

> 说明：本文件为从《美食家园》产品需求派生的阶段实施安排，阶段划分与顺序是执行规划，非原始需求新增功能。
> 产品权威来源：`docs/requirements/product/01-roles-and-functions.md`、`02-pages.md`、`03-quality-and-appendices.md`。

## 阶段目的
建立产品需求与实际 Android 仓库的一致基线，确定已知技术边界，并把会阻碍当前任务的未决业务问题显式记录，而不是预先替用户决策。本阶段以需求/工程核查为主，不新增产品能力。

## 本阶段完整工作范围
1. 核对已有 Android 项目位置、模块与页面、构建入口、依赖、Git 状态、实际已有功能；没有仓库或没有构建环境时，如实标记缺失，不虚构检查结果。
2. 核对 Figma 原型是否能访问，确认已提供的页面参考图、资源/接口是否存在；缺失时只记录依赖。
3. 建立统一用户体系、五导航、好友可见/公开菜谱、好友免费预订、订单双视角和未来规划边界的约束映射。
4. 对【待确认】事项按即将实施的阶段关联：优先关注未登录可浏览范围、登录入口、好友关系、菜谱编辑字段、预订状态/确认弹窗；仅在实施会受阻时请求用户决定。
5. 初始化阶段进度记录和可用的最小代码实施/验收约定，不另造产品架构、不批量生成未计划功能占位。

## 交付与 Gate
- 在 `02-progress.md` 给出已确认工程事实、缺失依赖、待决事项、建议第一步及证据来源；如项目尚不存在，不把运行验证写成 PASS。
- `python scripts/phase_flow.py check` 可用且通过目录、当前副本和容量校验。
- 用户审核后明确接受 P00，才将 P01 全部需求装入 `CURRENT_TASK.md`。

## 需求引用与禁止事项
映射产品文档 1、2、3.1、5 章及附录 D。不得改变五个入口、先行开发付费/配送或将原文未知的业务规则标记为已确认。
