# P08 · 菜品预订与双向订单管理

> 说明：本文件为从《美食家园》产品需求派生的阶段实施安排，阶段划分与顺序是执行规划，非原始需求新增功能。
> 产品权威来源：`docs/requirements/product/01-roles-and-functions.md`、`02-pages.md`、`03-quality-and-appendices.md`。

## 阶段目的
完成该产品的特色业务：好友免费预订菜品，经预订确认后形成订单，由提供方接单/拒单及备货，并在双方视角保持状态一致。

## 本阶段完整工作范围
1. 菜谱详情和好友可预订菜品列表均沿用“加入购物车”按钮，跳转**预订确认弹窗**，而非独立购物车/支付页。
2. 菜品预订详情显示好友头像、昵称、评分、预计送达时间及符合权限的可预订菜品；评分和时间来源未确认时禁止捏造实际值。
3. 确认提交成功后，预订方“我的订单”与提供方“我的销售”访问同一笔关联订单。两标签展示相应用户有权操作的订单。
4. 提供方按当前有效订单规则接受/拒绝并管理备货；订单列表/详情保留原文例举的“待接受”“待取货”等状态，但**不能默认这些构成完整状态机**。
5. 接单、拒单、重复点击、请求超时、回查和多端并发要具备最小数据一致性与错误反馈；实际状态和最终权限由持久化/服务端边界裁定。
6. 本阶段实施**前必须确认会影响契约的高优先级未知项**：提交字段、单/多菜品与数量、取消规则、如何进入“待取货”、什么算完成、通知形式、历史菜谱变更对订单的影响。不能把“待确认”自行变成默认订单状态或按钮。
7. 订单生成/处理结果应在消息通知入口可对应查看。收费、交换语音视频文字、配送平台均非本期内容。

## 验收要点
- 有权限好友可以确认预订；非好友、无权限或不可预订不能下单。
- 两种订单视角一致，接受/拒绝后的详情与列表实际同步；异常/重复请求不产生伪成功或重复业务。
- UI Gate 提供两用户互测步骤、拒单、失败/重试、状态一致性与预订通知检查；合同未确认时该阶段保持阻塞而非伪验收。
