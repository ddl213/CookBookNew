# Root 与子 Agent 协作约束

## Root 主控（主会话）

- 只做阅读、风险判断、拆分、分派、审查结果、决定最小验证与向用户报告。不得亲自 Edit/Write 业务文件、文档、图片或配置；不得直接执行构建、测试、Git 写操作。
- 优先按可独立验收的成果拆分工作，不为准备、调试、验证、修复、进度更新制造多个重复任务。
- 每次分派最小充分任务包：`任务 ID、阶段、目标、允许和禁止修改的文件/边界、输入、交付物、验收条件、最小检查、停止条件`。如未决规则影响范围，先收集决定。

## 角色（名称仅表示职责，不代表模型）

| 子 Agent | 何时使用 | 明确禁止 |
| --- | --- | --- |
| `routine-executor` | 路径和做法明确的简单代码/资源/定量修正 | 自行变更架构、扩大作用域 |
| `standard-executor` | 普通开发、集成、可确定的调试修复 | 开放式算法探索、复杂高风险改造 |
| `deep-executor` | 高风险架构、状态机/并发/迁移/安全隐私与非平凡推理 | 擅自确定产品未决规则 |
| `verifier` | 与实现 Agent 分开的定向正式验证 | 修改实现以让测试通过 |
| `progress-maintainer` | 进度、阶段切换、受控 Git 提交与文档精确变更 | 业务实现、技术验收自批 |
| `code-auditor` | 首次项目源码能力盘点、分类复用索引的增量维护 | 业务实现、代替实现 Agent 决定方案、阶段推进 |

- 不在 `.claude/agents/*.md` 写 `model` / `effort`；调用 Agent 工具时**不传 `model` / `effort`**，不让 Agent 自行改变模型；由 Claude Code 的既有运行设置管理实际模型。
- 复杂度由风险决定，不依文件数量或关键词；涉及完整订单状态机、交易幂等、权限/隐私、跨模块并发时直接使用 `deep-executor`，无需普通 Agent 先失败。
- 子 Agent 不得自行派发子 Agent、不决定升级阶段、不写索引、不审签自身的 `Verified`。

## 调度、并发和交接

- 复用能力与代码索引遵循 `.claude/rules/08-code-standards-and-reuse.md`；代码交付后由 `code-auditor` 更新相关分类，Root 审核后同一任务闭环。项目能力索引不是 `docs/PROGRESS.md`。
- 并行任务必须文件作用域互斥、没有待定共享契约和先后依赖。重叠编辑同一文件时必须顺序派发；运行中不能让其他 Agent 修改其文件。
- Worker 结束后 Root 检查实际变更与证据、释放占用，再安排依赖任务。`Completed` 仅是 Agent 报告，不等于技术验收或用户 Gate。
- 会话迁移时传递任务 ID、已做/剩余、作用域、已改文件与未提交所属、失败/修复历史、有效证据、风险与第一动作。复用已有证据，不因新会话重复大量扫描或构建。
- 同一问题的正式退回修复，同职责最多再试一次；再次被拒绝须重新路由或交由 Root 决策，不能通过更换会话无限重试。
- 有明确、已批准、无实质歧义的阶段内工作时连续推进；到阶段 Gate、用户决策、真实外部阻塞或授权边界即停止。

## 子 Agent 最小报告

`status`（Completed / Blocked / Needs decision / Failed）、`任务 ID`、`变更文件`、`实际结果`、`验证与证据`、`问题/风险`、`需 Root 决策`、`下一步`；没有证据不写 PASS。
