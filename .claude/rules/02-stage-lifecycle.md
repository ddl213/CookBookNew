# 阶段索引、当前任务与档案

## 唯一数据源

- `docs/PROGRESS.md`：**唯一状态索引**。只允许 `已完成 / 当前 / 未完成` 三组阶段名称，每阶段恰出现一次；名称必须与对应 `01-requirements.md` 的一级标题完全相同。链接可定位需求，不加小任务、人员、日期、测试结果或长段进度。
- `docs/CURRENT_TASK.md`：**唯一当前任务文件**。完整复制当前阶段的 `01-requirements.md`，不得删节、摘要、混入状态/评论或把阶段内小任务当作下一个阶段。
- `docs/phases/Pxx-slug/01-requirements.md`：该阶段**只读需求源**；`02-progress.md`：唯一当前阶段细粒度工作记录；`03-history-NNN.md`：仅超限时的历史归档。
- 阶段目录按两位数顺序命名 `P00-...`、`P01-...`；禁止跳号、重号、复用已验收阶段目录。阶段顺序以目录数字为准，不以编辑时间或聊天顺序为准。

## 阶段内执行

1. Root 读取索引、当前任务和当前进度，核对实际工程和前置依赖。
2. 一个“小任务”是可独立核验的成果。准备、实施、局部修正、定向验证、记录与提交不因换 Agent 或会话而更换任务 ID。
3. 初次实施或实质变更路由/范围/阻塞时，由进度子 Agent 在当前 `02-progress.md` 先记任务、职责、边界、依赖和验收条件；不在索引写明细。
4. Root 派发实施 Agent；审阅稳定结果；再派独立验证 Agent。收到结果后进度 Agent登记证据与状态。
5. 子任务 `Implemented`（实现未验收）→ `Verified`（检查通过、Root 技术接受）→ 阶段 Gate（用户明确接受）。未接受前继续同一阶段，不覆盖当前任务。

## 切换阶段（仅限用户明确 Gate 通过后）

1. Root 确认该阶段全部约定交付及 UI 手动验收完成，用户明确说接受本阶段。
2. 进度 Agent 在旧 `02-progress.md` 写 `- 用户阶段验收：已接受`，`- 验收依据：...`，保留实际用户结论、日期及剩余风险。
3. 由进度 Agent 执行 `python scripts/phase_flow.py advance --user-accepted`。脚本先核对当前进度已记录验收，再将下阶段**整个** `01-requirements.md` 写入 `CURRENT_TASK.md`，最后重建索引。
4. 切换后只在新 `02-progress.md` 记录新阶段的小任务和后续执行范围。切换只负责**准备下一任务**，不得当作用户已授权直接开始下一阶段实现。
5. 最后阶段使用 `finish --user-accepted` 标记终态；不能再凭空生成下一阶段。
6. 如果任一校验失败或阶段记录矛盾，停止并核对，不使用覆盖式“修复”丢弃证据。脚本支持 `check` 检查一致性。

## 上限与分拆

- 所有 `.md` 单文件 ≤ 16,384 UTF-8 bytes；建议在达到 12,288 bytes 前将**已验收、无活动依赖**的旧明细移入同阶段 `03-history-001.md` 等顺序文件。
- `02-progress.md` 保留目标、活动任务、门禁、阻塞、最新决策、证据引用、归档链接与下一动作；旧验证摘录/已完成任务记录归档，不能仅为了省空间删掉失败或否决历史。
- 产品需求按原章节拆到 `docs/requirements/product/`；后续超过阈值继续按章节拆文件，不压缩语义、不跨阶段挪动验收内容。
- `scripts/phase_flow.py check` 是大小、路径和索引一致性检查；它不证明功能实现成功，也不替代用户 Gate。
