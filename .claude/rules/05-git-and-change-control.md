# Git、安全和变更边界

- 项目根目录是含 `CLAUDE.md` 的仓库根；子目录不应被临时 `git init` 当作新仓库。
- 每个实施任务前由实施 Agent 检查 `git status --short`，确认已有用户改动和文件所有权。不得在未授权时清理、覆盖、stash/reset/revert 用户改动；若与作用域冲突，停止并交 Root。
- Root 不直接运行 Git 变更；仅在 Root 已核实 `Verified`、验收证据有效、进度已记录、待提交文件明确后，由 `progress-maintainer` 执行最小暂存及**本地提交**。
- 提交前检查 staged diff，禁止把无关改动一起提交。首次仓库基线/`git init` 需要用户明确批准；不得伪造历史阶段的提交记录。
- 建议提交信息 `feat(P04-T02): ...` 或 `fix(P08-T03-F01): ...`，任务和阶段 ID 与进度记录一致；不因换 Agent 单独提交空管理文件。
- 无用户明确授权，禁止 `git push`、创建远端、公开上传仓库、强推、改写已接受历史或使用可能丢弃改动的 `git reset --hard`、`git clean -fd` 等命令。
- 密钥、令牌、私人聊天数据、用户私人图片及构建/缓存/IDE 中间文件不得提交。隐私和可见性检查须经过真正的数据访问控制，不能只藏前端按钮。
- 不擅自升级依赖、替换技术栈、修改公共接口或更改已验收产品需求；影响既有契约的变更先记录原因及迁移/回滚影响。
