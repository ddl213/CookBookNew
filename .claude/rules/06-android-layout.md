# Android 新增与修改 UI 规范

本规范用于**新增或本任务实际修改的 UI**。已有页面或复用页面优先保持当前项目风格、结构与适用现有实现，不为了统一风格强行重构无关布局。

- XML 布局优先 `ConstraintLayout`，**禁止新增或在修改范围内使用 `FrameLayout`**；只有简单布局或者更简洁清晰的实现才使用 `LinearLayout`。减少无意义嵌套。
- 不机械抄设计稿固定宽高；优先 `wrap_content`、约束完整的 `0dp`、百分比、`dimensionRatio` 等自适应方式；不同屏宽、字体缩放、长标题/昵称不得溢出、遮挡、重叠或截断关键操作。避免为方便布局硬编码每个 View 的宽度或高度。
- Figma 中一个完整的视觉素材若实际是合成图片，作为单张图片资源呈现，不通过提取中间文字重建多层 ViewGroup。只有明确需要动态文字、无障碍/本地化或交互的内容才拆成控件；不改变设计意图。
- 实施 UI 前先查 `docs/code-index/03-custom-views-ui.md` 和 `04-layouts-styles-res.md`，优先复用已经存在且适用的控件、布局及资源。
- 视觉基准优先用现有项目中**大量重复使用的同类功能/二级页面**背景、按钮、圆角、状态样式，不凭一个孤立页面臆造新设计。产品原始风格为白色、暖橘/黄色、圆角卡片。
- 对本任务涉及的 UI：确认主交互、返回/导航、加载/空/错误状态、权限差异以及至少一种小屏/大字体场景；提供可复现的用户手动验收步骤。
- 不为缺失图片/原型自行伪造视觉素材或把参考截图当作可交互组件；及时上报真正缺失的资产或设计决策。
