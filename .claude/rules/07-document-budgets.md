# 文档预算与记录边界

- `CLAUDE.md`：目标 ≤ 6 KiB，硬限制 16 KiB；只写核心入口与硬规则，不复制各主题规则。
- `.claude/rules/*.md`：一文件一主题，建议 ≤ 8 KiB；`.claude/agents/*.md`：一 Agent 一职责，建议 ≤ 6 KiB。
- `docs/PROGRESS.md`：只允许阶段名称和链接，每阶段在三组中恰出现一次；不记任务数、人员、失败、证据、摘要。
- `docs/code-index/00-INDEX.md`：只记代码能力类别导航、盘点范围/状态；每类一份能力表，实际项目核查后填写。接近 12 KiB 按子功能拆为有序子表，仍遵守 16 KiB 硬限制。首次盘点和增量维护见 `08-code-standards-and-reuse.md`。
- `docs/CURRENT_TASK.md`：不改写、注释、勾选或删节，必须等于当前阶段完整需求文件。
- `docs/phases/Pxx-*/02-progress.md`：不新建每任务状态文件；使用紧凑记录维护任务表、活动阻塞、决策、技术验收、人工 Gate 与归档引用。
- 达到 12 KiB 的活跃进度文档应准备归档已完成历史；16 KiB 是绝对上限。一个历史文件满后用 `03-history-002.md`，先核对全量迁移无丢失，再从活动进度移走历史副本。
- 切换阶段时只更新当前进度、索引与当前任务；冻结前一阶段的已验收记录。历史勘误追加有依据的修正说明，不悄悄重写原有验收结论。
- 使用 `python scripts/phase_flow.py check` 核对文件预算、索引一致性和当前任务完整复制。脚本仅检查结构，不能宣称运行时业务验证。
